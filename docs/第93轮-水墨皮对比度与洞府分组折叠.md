## 一、先量再改：把「看不清」变成数字

写了 `qa/audit-contrast.mjs`：把 12 个洞府页签 + 世界地图 / 战斗 HUD / 坊市 / 对话 / 暂停**真的渲染出来**，遍历带文字的可见元素，逐元素算「实际背景色」与「文字色」的 WCAG 2.1 对比度。

三个容易算错的地方先修掉：

| 坑 | 处理 |
|---|---|
| 卡片边框渐变被当成背景，大面积误报 | `bgOf()` 沿祖先链逐层合成半透明底，渐变取各色标均值 |

| 禁用按钮本来就不要求达标 | 按 WCAG 1.4.3 豁免，单独计数，不混进主结果 |

**基线**：用同一份最终脚本跑上一版（`HEAD`，独立 worktree + 8124 端口）—— **196 处不达标**。
（中间曾记过 147、21，那是脚本自身还在修背景合成时的中间值；最终两份记录已统一口径，见 `qa/contrast-before.txt` / `contrast-after.txt`。）

## 二、根因与改法

### 1. 字色是给深色皮设计的，换皮只换了底

| 稀有度 | 原色 | 宣纸底 #efeadb 上 |
|---|---|---|
| 至宝 | `#ffd24a` | **1.22:1** |
| 仙品 | `#8ff0e0` | **1.13:1** |
| 凡品 | `#cfd6e2` | **1.20:1** |

不是「偏淡」，是肉眼基本看不见。而这些色值是**写死在 HTML 字符串里**的，皮肤只换得到 CSS 变量，换不到内联 `color:`。

**改法**：`game.js` 加 `rarize()` —— 只认 `RARITY` 里那 6 个已知色值，把内联 `color:#xxxxxx` 换成 `color:var(--rar-N)`，其它 color 原样放行。色板分两套：

- 根变量（深色皮）：仍是原来的亮色
- `body[data-skin="guigu"]`：整组换成深墨矿物色（凡品淡墨 / 良品竹青 / 上品花青 / 珍品紫 / 至宝赭金 / 仙品松石，实测 5.0~7.5:1）

5 处 `innerHTML` 调用点统一过 `rarize`：洞府体、属性页、坊市列表、世界地图、掉落飘窗。另外「未佩」从硬编码 `#7c7768` 换成 `var(--text-4)`，深色皮这边也跟着改善。

### 2. 黑蒙版底 + 墨色字，叠死

| 位置 | 改前 | 改后 |
|---|---|---|
| 进阶 / 材料行 | 底 `rgba(0,0,0,.26)`，纸上是一块墨渍，字也是墨 → **2.0:1** | 淡墨底 `rgba(74,68,56,.055)` + 墨线，徽章改小签 |
| 主行动按钮 / 选中页签 | 墨字压赭石渐变 **4.06:1** | 渐变提亮到 `#d6a67e→#c88f63`，**6.9:1**（仍是赭石） |
| 世界地图统计条 | 黑底亮字 **2.26:1** | 淡墨底墨字 **8:1** |
| 区块标题 / 成算 / 材料签 / 行迹段头 | 3.2~3.8:1 | 统一压到 5:1 以上 |
| 弱提示 `--text-4` | `#6b665a` 4.6:1 | `#5a5142` 7:1 |

### 3. `opacity` 连字一起压淡

`.45` 会把 5:1 的字压成 2:1，而这些内容玩家仍需读（这件是什么、缺哪一味、还差哪个境界）。locked 装备行 `.78→.94`、未解锁地图 `.62→.88`、禁用按钮 `.62→.74`，底色字本身再加深一级。

### 结果

| 皮肤 | 改前 | 改后 |
|---|---|---|
| 水墨 `guigu` | **196** | **0**（另有 6 处禁用控件，按 1.4.3 豁免） |
| 深色 `jin`（回归） | **91** | **82** —— 改善 9 处，**无回归** |

深色皮剩下的 82 处是历史遗留（未解锁地图卡 `opacity:.45`、`em` 小字 4.41:1 等），不属本轮范围，且没有被这轮改动扩大。

## 三、洞府分组折叠

一次只开一组的手风琴，`G.caveFold[tab]` 记住每个页签开着哪组；**点开一组其余自动收，再点同一组全收**；没选过时默认开玩家当前所在的大境界，进来先看到自己这一档。

| 页签 | 分组依据 | 组数 |
|---|---|---|
| 装备 | `SLOTS`：兵器 / 护甲 / 佩饰 / 符宝，组内稀有度降序 | 4 |
| 功法 | `s.minLv` 归大境界 | 11 |
| 进阶 | 一关一组，默认开「当前该破的那一关」 | 13 |
| 炼丹 / 炼器 / 制符 | `r.req` 归大境界 | 5 / 4 / 1 |

境界名有「炼气期一层」「筑基初期」「大乘期」三种写法，不能靠切后缀 —— 用 `BIG_REALM_KEYS` 关键词表取第一个命中项；组头「炼气」念成「炼气期」，「真仙 / 金仙 / 太乙 / 大罗」本身已完整，不再加「期」。

点击处理**直接切 class，不走 `renderCave()`**：重绘会把滚动位置弹回顶部，在长列表里点靠下的组等于白点。

### 踩坑：点组头那一行会跳 27px

第一版补偿是 `scrollTop += (y1 - y0)`，验收实测位移 27px。加日志探针后看到：

```
点击前    st=398   y0=232.7
class 切换后 st=585  y1= 65.1   ← 浏览器把滚动条推到了新底部
补偿后    st=417   top=215.6   ← 期望 232.7，还差 17px
```

两件事叠在一起：

1. **滚动锚定 / 按钮归位**：折叠让内容高度从 884 → 859，浏览器顺手把 `scrollTop` 推到新的 max。于是 `y0` 和 `y1` 根本不是在**同一个滚动基准**上量的，补偿量里混进了浏览器自己的那次滚动。
2. **flex 容器要两遍布局才稳定**：第一遍 rect 和第二遍之间又差了约 17px。

**修法**：先把 `scrollTop` 强制拉回 `st0` 消除浏览器那次滚动，再迭代校正最多 3 轮（每轮读一次组头位置补一次，被 scrollTop 上下限钳住时自动停手，不空转）。

**结果**：组头屏幕 y **300 → 300，位移 0px**。

## 五、教训

1. **皮肤不是「换个底色」，是一整套色板。** 字色只要写死在 HTML 里，换皮就只换得到底、换不到字。凡是会随皮肤变的颜色都必须走 CSS 变量。
2. **对比度审计要算「合成后的实际背景」。** 只看 `color` / `background-color` 会同时误报（边框渐变）和漏报（`opacity`）。
3. **滚动锚定是隐形的第三方。** 布局一变，浏览器可能已经动过 `scrollTop`；「前后各读一次 rect 再补偿」必须先恢复基准，否则算的是两个坐标系的差。
