# 第112轮 · 剧情只演一次（重复刷图不再重念剧情 / 不再二次跌境界）

## 一、问题（Jerry 提出）

> 让每个有剧情对话的地图、或一定会因剧情安排跌落境界的地图，加入条件才能触发剧情；经历过一次了，再重复刷这个地图将不再会触发剧情对话和剧情跌落境界。

改前实际行为：

| 触发点 | 改前 | 后果 |
|---|---|---|
| 战斗内定时剧情（`window.STORY`） | 只认内存里的 `s.done`，而 `beginMap` 每次都 `for (const s of STORY) s.done = false` | 同一张图刷第二遍，开场剧情**每遍重念** |
| 地图 `intro` 过场（63 张） | 无任何"已看"判断 | 重刷**每遍重念** |
| `type:'story'` 剧情图（80 张） | 无判断，进门即整场演 | 重刷**每遍重演** |
| 收场台词 `outro`（72 张） | 无判断 | 重刷**每遍重念** |
| 坊市开场白（7 张） | 按「是否通关」判断 | **没通关就每进一次念一遍** |
| 古传送阵跌境界 | 判据 `!save.wounded`，而重修把修为补回来时 `save.wounded` 会被清空（`clearWoundedIfDone`） | 重修后**再进一次又跌回炼气期四层** |

> 注：`save.seen` 这个字段其实早就在记定时剧情 id，但 getter 只用内存 `s.done` 判重，落盘的账没被用上。

## 三、改法

### 3.1 一套记账口径（落在 `save.seen`，跨局跨读档）

| 类型 | 键 | 说明 |
|---|---|---|
| 战斗内定时剧情 | 原始节点 id（`hs_open`…） | 沿用历史字段，老档天然兼容 |
| 地图开场过场 | `intro:<图id>` | 同时覆盖坊市开场白 |
| 剧情图整场 | `scene:<剧情键>` | 破境图的 `_lock` 变体**单独记账** |
| 收场台词 | `outro:<收场键>` | 按"实际播的那一版"记 |

```js
function storySeen(key) {
  return !!key && Array.isArray(save.seen) && save.seen.indexOf(key) >= 0;
}
function storyMarkSeen(key) { /* 去重后 push + writeSave() */ }
```

**只在「真的演完」时记账**：看到一半退出、关页面都不算，下次仍会补上 —— 剧情不能因为意外而丢。

### 3.2 五类触发点接闸门

1. **定时剧情**：`if (storySeen(s.id)) continue;`，并把记账从"触发时"移到"演完时"。
2. **剧情图**：新增 `storySceneOf(m, id)` 算出"这一场到底是哪一版"，判过就 **`onStoryMapDone(m)` 直接走后果**（奖励 / 破境判定 / 跌境界一样不少，只是不再念）。
3. **intro 过场**：看过就直接 `afterIntro()` 开打（剧情战照常 `spawnBoss()`）。
4. **outro 收场**：念过就 `finishMap(m)` 直接结算。
5. **坊市开场白**：从"看 cleared"改成"看 intro 键"，没通关也不再逐次重念。

### 3.3 三条守住的边界

- **抉择类对话豁免**：`zhuji_out_ask`（要不要就此破境）每次都问 —— 跳过等于替玩家做决定。
- **料没齐不记正剧账**：破境图未备齐时那段中性兜底（"还差着…"）`key = null`，不记账；备齐后仍要演正剧。
- **账要记对版本**：`storySceneOf` 与 `storyLinesOf` 同口径，避免"记了 A 版的账、播的却是 B 版"。

### 3.4 跌境界一次性

```js
if (m.id === 'guchuan' && !save.wounded && !save.woundedDone) {
  ...
  save.woundedDone = true;   // 不回退的一次性标志
}
```

`woundedDone` 与 `wounded` 分开：`wounded` 表示"此刻修为受损"，重修完就该清；`woundedDone` 表示"这笔剧情代价已经付过"，永不清。

**旧档兼容**：读档时 `woundedDone: !!s.woundedDone || (cleared 含 'guchuan')` —— 已通关古传送阵的老玩家不会再跌一遍。

## 五、可复用经验

- **"已经给过的东西"要能问、能答、能落盘**。`save.seen` 早就存在，但 getter 只看内存标志，等于白记 —— 判断依据必须和落盘数据同源。
- **一次性代价不要跟"当前状态"共用一个标志**：`wounded`（此刻受伤）和 `woundedDone`（付过代价）混用，导致重修一清空就复发。状态会回退，历史不会。
- **跳过剧情 ≠ 跳过后果**：`showLines([], onEnd)` 会直接调用 `onEnd`，所以"不演"和"照走结算"可以是同一条路径 —— 不用为跳过单开分支。
- **否定断言要看"活"的证据**：`G.dialogId` 弹完不清空，用它判"是否在演"会读到上一次的残留，必须看 `state === 'dialog'`。
