# 凡人·长生劫 — 第 86 轮：招式视觉分型（Boss 不再只有圆珠）

> 起因：Jerry 报「特别 Boss，我只看到 Boss 只会打多个圆珠出来，没有其他攻击效果？」
> 结论：**属实，而且比"少"更严重——是"全一样"。**

---

## 一、评审：问题在哪

### 1.1 数据实测

把全部 Boss 招式表拉出来统计，共 **185 条招式**：

| 招式类型 | 条数 | 占比 | 改动前的视觉 |
|---|---:|---:|---|
| fan 扇形齐射 | 50 | 27.0% | 一颗紫红圆点 |
| ring 环射 | 24 | 13.0% | 一颗紫红圆点 |
| trap 定身 | 19 | 10.3% | **无**（只弹一行字） |
| summon 召群 | 16 | 8.6% | 召出小怪（可见） |
| dash 冲撞 | 14 | 7.6% | 几粒灰尘 |
| beam 贯刺 | 12 | 6.5% | 三颗紫红圆点排一行 |
| blink 瞬移 | 10 | 5.4% | **无**（只抖屏） |
| rain 天降 | 9 | 4.9% | 一颗紫红圆点从天上掉 |
| heal 回血 | 9 | 4.9% | 飘字（可见） |
| nova 爆发 | 8 | 4.3% | 一圈紫红圆点 |
| mist 毒雾 | 6 | 3.2% | 十颗紫红圆点慢慢飘 |
| pull 拉拽 | 5 | 2.7% | **无**（直接扣血+位移） |
| chill 冰封 | 3 | 1.6% | **无**（只弹一行字） |

### 1.2 根因（一行代码）

绘制端只有这一行，全部敌方子弹共用：

```js
for (const b of G.ebullets) drawSpr('ebullet', b.x, b.y, 1.4 * (b.r || 7) / 7, false);
```

`ebullet` 精灵是 **5×5 的紫红圆点**。所以：

- **109 条（59%）**招式产出的弹幕，在画面上是同一个东西，只差缩放
- 扇形齐射 = 5~7 个圆点
- 环射 = 14 个圆点
- 贯刺 = 3 个圆点排一列
- 天降 = 圆点从上面掉下来
- 毒雾 = 10 个圆点慢慢飘

实测十帧，子弹半径只有 `[7]` 和 `[7,17]` 两种取值——**画面上没有任何第二种形状**。

### 1.3 另一半问题：27 条招式"零视觉"

`trap` / `chill` / `pull` 这三类共 **27 条（15%）**，代码是直接 `hitPlayer(dmg)` + 飘一行小字。
玩家体验到的不是"被打了一招"，而是**血条莫名其妙少了**——这比画面单调更像 bug。

### 1.4 六维评分（改动前）

| 维度 | 分 | 说明 |
|---|:--:|---|
| 剪影可读性 | 1 | 所有招式同一个剪影 |
| 明度层级 | 3 | 弹体本身够亮，能和地面分开 |
| 构图与负空间 | 3 | 弹幕分布合理，不糊屏 |
| 风格一致性 | 4 | 与角色同一套像素笔触（这点本来是对的） |
| 技术合规 | 5 | 尺寸、性能都没问题 |
| **可用性** | **1** | **招式读不出来，15% 的招式完全看不见** |

**结论分档：重做**（可用性不过关，不是微调能解决的）。

## 二、改法：形由招式决定，色由来源决定

一条纪律先立住：**"这是什么招"必须写在形状上，不能只写在颜色上。**
玩家在混战里没有余力读字，也没有余力分辨"这个红点是火还是剑"。

### 2.1 弹体六型

| 形体 | 用于 | 笔触 | 色 |
|---|---|---|---|
| `orb` 珠 | 环射 ring | 三层同心：外光晕 / 珠体 / 白芯 | `#ff6a4a` |
| `shard` 碎刃 | 扇形齐射 fan | 菱形锐片 + 身后短尾（**有方向**） | `#ffd08a` |
| `blade` 光带 | 贯刺 beam | 沿速度拉长到 7.5 倍，前端尖尾部收细 | `#cfe8ff` |
| `drop` 坠物 | 天降 rain | 尖端朝下的水滴 + 竖直拖尾 | `#ffb060` |
| `mist` 雾团 | 毒雾 mist | 由外到内递浓的四层云 | `#d9f58a` |
| `heavy` 重珠 | 爆发 nova | 珠体 + 呼吸外环 | `#ff8a3a` |

### 2.2 地面三区（补上"零视觉"）

新增 `G.zones`，贴在纸面上的一层（按 0.42 压扁，与已有法阵同一口径）：

| 区域 | 用于 | 画法 | 效果 |
|---|---|---|---|
| `bind` 困阵 | trap 定身 | 阵纹双环 + 四向锁链，链条由外朝内收 | 站内持续减速 0.34 |
| `ice` 冰面 | chill 冰封 | 冷色面 + 六角冰晶（含支晶） | 站内减速 0.45 |
| `vortex` 漩涡 | pull 拉拽 | 三道螺旋实时旋转 + 中心核 | 每帧朝中心拽 |

**伤害纪律：仍然只在落招那一瞬一次性结算。** 地面区只加"看得见的范围 + 减速"，
不追加持续伤害——加视觉不该顺手改难度。

### 2.3 位移两型

| 招式 | 改动前 | 改动后 |
|---|---|---|
| `dash` 冲撞 | 几粒随机灰尘 | 起势炸两圈尘 + 沿途每 55ms 留残影环 |
| `blink` 瞬移 | 只抖屏 | 去程/落点各一对同心环，紫 + 白双层 |

冲撞方向线原本是 **5px 等宽、200px 长的硬直线**，看着像 UI 占位符；改成九段由粗到细、
由亮到暗的轨道。而且原来带 `kind === 'beast'` 条件——**人形 Boss 冲撞时完全没有方向提示**，已去掉。

### 2.4 天降补落地

原来 `drop` 从 `ty - 300` 落下后**径直穿过地面继续飞**，玩家看到的是"东西掉进了地底"。
现在砸到 `landY` 会炸开一圈冲击 + 三粒飞溅再消失。

## 三、配色纪律

### 3.1 一条硬教训

第一版毒雾用了 `#9fd97a`（绿）。**在绿草地上直接隐形**——实测截图里那一格几乎是空白。
现改为 `#d9f58a`（比草地亮一档的黄绿）。

> **规则：特效色只跟"背景明度差 ≥ 18 档"有关，跟"这个颜色代表什么"无关。**
> 毒是绿的，但草地也是绿的，这个绿就等于没用。

### 3.2 与皮肤的联动

全部走 `ctx.strokeStyle / fillStyle`，由既有 `inkify()` 拦截，水墨皮下自动转墨色系。
实测九格（`qa/shots/inkfx-contact.png`）：朱砂 / 赭石 / 花青 / 墨紫，无彩色残留。

## 四、验收

### 4.1 逐招实拍

`qa/shot-fxslab.mjs`，十一型各单独放一次、各截一张（金皮 + 水墨皮两组）。
所有形体都正确生成，且互相可区分：

```
orb 子弹14[orb]  shard 7[shard]  blade 3[blade]  drop 6[drop]  mist 10[mist]
heavy 16[heavy]  bind[bind]  ice[ice]  vortex[vortex]  dash  blink
```

### 4.2 真实战斗

`qa/shot-bossfx.mjs` 连续十帧。改动前后对比：

| 时刻 | 改动前 | 改动后 |
|---|---|---|
| 2s | 一排粉红圆点 | **一排金色扇刃** |
| 4~5s | 大圆圈预警 | 大圆圈预警（不变） |
| 6~7s | 一圈粉红圆点 | **一团黄绿毒雾罩住 Boss** |

| 项 | 结果 |

## 五、没做的（明确边界）

1. **没有新增玩法型招式**：持续光柱扫射、地刺、全屏冲击波这类需要新判定逻辑的东西，一个没加。
   本轮只做"已有招式看得见、分得开"，加新机制属于另一个立项。
2. **27 只 Boss 仍走同族招式表**：原著只点名未写战况，硬编等于自己编。
3. **同族精英招式相同**：族内已差异化，做不到每只独门。
4. **帧耗 +4.8% 未在低端机验证**：桌面 Chrome 数据，真机请用 `perf.html` 复测。

## 六、可调点

| 想改什么 | 改哪 |
