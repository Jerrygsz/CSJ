# 动作与打击感 · 实现说明

> 目标：**不引入任何新素材**，让《凡人·长生劫》里原本完全静止的角色有动作、让打击有反馈。
> 全部改动集中在绘制层（`js/game.js`），不动战斗逻辑、不动数值。

---

## 一、为什么只能在绘制层做

角色是一张静态字符网格（`js/sprites.js` 的 `rows` + `pal`），`drawSpr` 原来只有一句：

```js
ctx.drawImage(c, -w/2, -h/2, w, h);
```

零变换参数 —— 所以玩家、敌人、Boss、NPC、灵宠、同伴**全部静止**。画面里原本所有的"动"都来自别处
（飘字、受击白闪、境界光环、掉落物 bob）。

序列帧方案（仁者爱平台那类逐帧出图）在这个项目里不划算：它产出的是**侧视高精度角色**，
而本项目是**俯视 2D + 12×14 像素**，尺寸、视角、风格三重不匹配，等于重做一套美术。

能动的有三条路，都做完了：

| 层 | 做法 | 成本 |
|---|---|---|
| **A 特效层** | 剑光弧、符文环、火花、碎裂，全靠 canvas 画 | 0 素材 |
| **B 程序化变换** | 画的时候对同一张网格施加 scale / 位移 / 旋转 / 切腿 | 0 素材 |
| **C 手绘补帧** | 四张一组的跑步关键帧，直接写进 `js/sprites.js` | 0 素材 |

---

## 二、B：`drawSpr` 的四个动作

`drawSpr(name, x, y, sc, flip, tf)` 新增可选第 6 个参数 `tf`（变换）。

### 支点必须落在脚底

```
translate(x + dx, y + h/2 + dy)   →   scale(sx, sy)   →   drawImage(c, -w/2, -h, w, h)
```

以**中心**为支点做竖向 squash，角色会上下同时张开，看起来像原地抽搐；
以**脚底**为支点缩放才是"蹲下去"，脚不离地才站得住。

`sx=sy=1、rot=dx=dy=0` 时，结果与改造前那句 `drawImage(-w/2,-h/2)` **逐像素一致** —— 老画面不会因为这次改造而漂移。
这条有守门断言（`qa/verify-anim.mjs` 第 1 节，注入 3px 偏移会立刻报错）。

### 四条曲线

| 动作 | 触发条件 | 曲线 | 幅度 |
|---|---|---|---|
| **待机呼吸** | 站着不动 | `sy = 1 + sin(2.1t)·0.022`，`sx` 反向 0.012 | 竖向 ±2.2% |
| **跑** | `p.moving`（真的在走） | 上下颠 1.9px + `sx/sy` 挤压；人形精灵改走**手绘四帧**（见下），没有帧的才切腿 ±1.6 精灵px | 步频 ≈ 3Hz |
| **出手** | `p.atkAnim > 0` | 0.28s：后收 3px（0.07）→ 前冲 7px + 横向拉伸 18%（0.05）→ 阻尼余弦过冲回弹（0.16） | 位移 ±7px |
| **受击** | `hitFlash / hurtFlash > 0` | 压扁 + 后仰，0.12s 内恢复，`k²` 衰减（收得快） | 位移 4.5px |

优先级：**受击 > 出手 > 跑 > 待机**。被打的瞬间不该还在迈步。

### 切腿为什么必须按列

上半身和下半身按**行**切开、左右错位 —— 只是"抖"。
正确做法是把下半身按**列**切成左右两条腿，各自沿竖直方向反向抬起（见 `blitSprOn` 里 `sliceAmp` 分支）。
正面朝向的角色只有这一条路能迈腿，因为网格里根本没有侧面。

⚠️ 只能**往上抬、不能往下压**：腿区域正好贴着精灵画布底边，往下偏移的部分会被裁掉，看起来就是"一条腿凭空没了"。

> 切腿是**没有手绘帧时的兜底**。狼、兽形、飞行类走这条；人形精灵现在走 C 的手绘四帧。

### 谁在动

| 角色 | 动作 |
|---|---|
| 主角 | 呼吸 / 跑 / 出手 / 受击（全套） |
| 敌人 · Boss | 跑（人形与兽形都切腿）+ 受击 |
| NPC | 呼吸 |
| 灵宠 · 同伴 | 原有 bob（未叠加，避免双重浮动） |

无腿或飞行的精灵（蛇 / 蝙蝠 / 火灵 / 冰凤 / 海兽 / 飞鸽）只给悬浮浮动，不切腿 —— 切了就是抖。
名单在 `NO_LEG`。

### 出手节流 0.42 秒

功法会自动连发（每 0.3~1.2 秒一次）。不节流的话主角会一直抽搐，像触电。
节流后最多 2.4 次/秒，读起来是"人在连续出招"，而不是"触电"。

**剑光弧 / 符文环跟身体同一次出**（`playerStrike()` 返回 true 才 spawn）——
不允许出现"身体没动、刃在挥"。

## 三·补、C：手绘跑步帧（四帧一轮）

程序化切腿只能把整条腿上下挪 1.6 个精灵像素，**挪不出形状**。
在 1.7 倍缩放下那约等于屏幕上的一个点，看得见"在动"，看不出"怎么动"。
所以给跑步补了四张手绘关键帧，直接写在 `js/sprites.js` 里，不增加任何文件。

### 一套帧，十几个精灵复用

```js
const RUN_LEGS = [
  ['..KXXKKXXK..', '..KXK..KXK..', '.KKK...KXK..', '.......KKK..'], // ① 左提膝外摆，右腿撑地
  ['..KXXKKXXK..', '...KXKKXK...', '...KXKKXK...', '...KKKKKK...'], // ② 并步：双腿收回身下
  ['..KXXKKXXK..', '..KXK..KXK..', '..KXK...KKK.', '..KKK.......'], // ③ 右提膝外摆，左腿撑地
  ['..KXXKKXXK..', '..KXK..KXK..', '.KXK....KXK.', '.KK......KK.']  // ④ 蹬开：双脚外八
];
```

`X` 是**身体色占位符**，逐精灵替换成自己的袍色/布色/皮色。
项目里的人形精灵（主角、内门弟子、女修、鬼物、匪徒、刺客……）身架是同一套 12×14 网格，
末四行都是同一个腿块，所以一组帧覆盖 13 个精灵：

`hanli · bandit · assassin · hermit · disciple · rogue · wangchan · jinqing · guixiu · laoyu · neimen · linmo`
外加 16 宽的**墨大夫**单独一组（`RUN_LEGS_MO`）。

帧只换**末几行腿块**，腿以上的行与原图逐像素一致 —— 这条有守门断言
（`spriteCmp` 量第一个不相同的行，必须落在腿块里）。

### 相位 → 帧名

```js
const q = Math.floor(gait / (Math.PI / 4));
frame = frames[((q % 4) + 4) % 4];
```

`gait` 每走 **π** 就是一整轮（两条腿各抬一次），所以一帧占 π/4，
正好对上程序化版 `sin(2·gait)` 的四个象限：左提膝 → 并步 → 右提膝 → 蹬开。
周期是 π 而不是 2π，这点也有断言守着。

配套两个小决定：

- **起伏峰值挪半个象限（π/8）**：并步那两帧才是人离地最高的时刻。不挪的话最高点落在提膝帧上，看着像"抬腿时往上蹦"。
- **有帧就关掉切片**（`tf.sliceAmp = 0`）：帧里腿的形状已经画好了，再切就是两条动画打架，退回成"抖"。

### 袍色：最容易漏的一个坑

主角的袍色随境界、甲色随护甲变（`buildHeroSprite` 会整体替换 `Sprites.hanli`）。
**帧不跟着换，人一跑起来袍子就闪一下回练气期的绿** —— 而且只有真穿上护甲才看得见。

所以 `applyHeroSprite()` 里四张帧一起换（`buildHeroRun(look)`，按配色 key 缓存）。
守门断言直接比对身份：`Sprites['hanli_run0'] === buildHeroRun(heroLook())[0]`。
这条**实测能拦**：把那两行注掉，立刻报两处失败。

### 谁走帧、谁走切片

| 精灵 | 跑 |
|---|---|
| 13 个人形（含主角、墨大夫） | 手绘四帧 |
| 狼 / 兽形 / 飞行类 | 程序化切腿（兜底，`runFramesOf` 返回 null 就自动退回去） |

没有帧的精灵不会因此不会动 —— `tfRun` 里 `framed` 为假时整条老路径原样走。

---

粒子/特效统一走 `drawPart(pt)` 一个出口。原先分成"先画环、再画方块"两个循环，
每加一种特效要同时改两处条件，漏一处就会被当成方块画出来。

| 特效 | 数据标记 | 出现时机 | 画法 |
|---|---|---|---|
| **火花 spark** | `spark:true` | 所有命中 | 细长线段，尾巴永远朝速度的反面拖；重力改向时尾巴跟着下垂 |
| **剑光弧 slash** | `slash:true` | 剑系（sword / qingmang / blood）出手 | 三段同弧叠加：外焰 9px / 刃 3.4px / 白芯 1.4px；前 31% 张开，之后变细变淡 |
| **符文环 rune** | `rune:true` | 法术系出手（火蛇 / 三焰扇 / 金光 / 天雷） | 双圈 + 12 道刻痕旋转；**按 0.42 压扁**才是画在地上，不压就是立着的铁圈 |
| **碎裂 shatter** | `shatter:true` | 敌人死亡 | 用它自己的精灵切 3×3，9 块各自飞散 + 旋转 + 轻微放大 + 下坠 |
| **命中白闪** | — | 敌人/Boss 受击 | **纯白剪影精灵**（`whiteSprite`，`source-in` 刷白）叠在同姿态上 |

### 修掉的两个旧问题

1. **命中白闪原来是 `fillRect` 一个白方块** —— 那是个方块，不是被打白的形状。
   现在用 `source-in` 把精灵的非透明像素刷成纯白、缓存起来，叠在**同一个姿态**上
   （不跟姿态走的话，闪出来的是没在动的那一帧，一眼假）。
2. **主角受击原来糊一层不透明红圆** —— 人是被提示了，但位置也看不见了。
   改成一圈红边 + 10% 淡染，打起来还能看清自己站在哪。

### Z 序

`rune` 是地面特效，在**所有角色之前**单独画一遍（`render()` 里 `if (!pt.rune) drawPart(pt)` 把它从主循环里摘出来）。
不这么做，符文环会压在腿上，变成呼啦圈。

## 四、验收

```
node qa/verify-anim.mjs     # 113 项守门
node qa/shot-anim.mjs       # 出图到 qa/shots/anim-*.png
node qa/shot-frames.mjs     # 手绘帧对照表 → qa/shots/anim-frames.png
python qa/compose-anim.py   # 拼四姿态 / 四帧 / 连拍对比图
```

`verify-anim.mjs` 113 项分 13 节：绘制基座没挪位 / 四态像素互异 / 四个方向正确 /
白闪是剪影 / 剑光 / 符文 / 碎裂 / 敌人受击 / **手绘帧（尺寸、只改腿、帧序、占位符、相位映射、有帧关切片、白闪跟帧、袍色跟着换）** / 零报错。

守门断言里最要紧的几条：

- **无变换时角色一个像素都不许挪**（`spriteProbe` 量墨迹外框，注入 3px 偏移立刻失败）
- **四态像素各不相同**（用 alpha 校验和比对，曲线改了但画出来一样 = 白改）
- **帧只改腿**（`spriteCmp` 第一个不相同的行必须落在腿块里；袍缘行照着原图写是故意的，所以只能要求"≥"不能要求"=="）
- **相位映射周期是 π 不是 2π**，负相位也要按象限回绕
- **帧和立绘同一套袍色**（身份比对，实测把那两行注掉会同时报两处）

截图脚本有个技巧：剑光弧只活 0.2 秒、碎裂 0.4 秒，而截图链路本身要一百多毫秒。
所以先把状态切到 `pause`（`update` 不跑、`render` 照跑）冻住那一帧再截。
跑步的四帧条是**冻结在每个象限正中**截的（`gait = q·π/4 + π/8`），
连拍条则是真按住方向键、让 `update` 自己推进相位 —— 后者证明帧序不是手摆出来的。

## 五、还没做的（候选）

- **D 换 CC0 素材**：把 12×14 换成 16×16 或 24×24 的公开像素人，动作帧天然齐。代价是整套角色重画。
- **补帧只补了跑**：待机呼吸、出手、受击仍是程序化变换。要的话可以同样手绘（出手 3 张：抬手 / 挥 / 收）。
- 攻击命中瞬间的**屏幕微缩放**（impact zoom）：现在只有 `G.hitStop` 冻结，没有镜头推拉。
- 没配帧的精灵（狼、兽形、飞行类）仍走程序化切腿 —— 要统一手感得给它们也各画一组。
