## 0. 已确认前提与待确认项

**已确认（从代码实测得出，不猜）**

| 项 | 结论 | 依据 |
|---|---|---|
| 运行形态 | 原生 HTML + CSS + Canvas 2D，无构建工具 | `index.html` 直接引 `js/*.js` |
| 世界层分辨率 | 逻辑宽固定 **480**，逻辑高 **864–1120 连续可变** | `resize()`：`wantH = min(1120, max(BASE_H, 480 × 视口高/视口宽))` |
| 世界层缩放 | `scale = min(视口宽/480, 视口高/H)`，Canvas 按此比例绘制 | 同上 |
| **UI 层坐标系** | **DOM 元素用物理 CSS px，不随 canvas 缩放** | `#stage` 只改 `style.width/height`，未用 `transform: scale()` |
| 现用字体 | `KaiTi / STKaiti / Noto Serif SC / SimSun` 楷体族 | `body { font-family }` |
| 风格锚点 | 国风仙侠：金褐主色 `#c9a24a`、亮金 `#ffd24a`、米白 `#f2e8d5`、深靛底 | 全表统计 |
| 设备安全区 | 已接 `env(safe-area-inset-*)`，加在 `#wrap` 的 padding 上（整体内缩） | `:root` + `#wrap` |

> **最关键的一条**：世界层会缩放，UI 层不会。所以 UI 上写的 `12px` 在 375 宽和 430 宽的手机上**都是 12 物理像素**，不随画面一起缩放。这决定了字号必须按物理 px 定阶梯、并且要按视口宽度做断点 —— 不能沿用世界层的逻辑坐标思路。这也是下文"小屏字偏大、大屏字偏小"的直接原因。

**待确认（需要你拍板，我不擅自定）**

→ 已于 v1.1 全部拍板，见 §0.1。

## 0.1 决策记录（2026-10-24 确认）

| # | 议题 | 决策 | 落实方式 |
|---|---|---|---|
| 1 | 风格基调 | **保持金褐国风**，不改主色 | 主色仍为 `#c9a24a` / `#ffd24a` / `#f2e8d5`；本轮只动结构、字号、命中区与令牌化，不动色相 |
| 2 | 字体兜底 | **接受思源宋体兜底** | `font-family` 改为 `KaiTi → STKaiti → Kaiti SC → Source Han Serif SC → Noto Serif SC → serif`，把系统宋体（SimSun）从链路里摘掉 |
| 3 | 洞府页签 | **不分组，保持 10 个页签现状** | §4 P1-6 **作废**。操作路径不变 —— 已养成的手部记忆比省一个孤格重要 |

**关于决策 2 的补充说明（供你判断是否要更彻底）**：思源宋体是宋体骨架，与楷体的字形差异仍然存在（横画更平、撇捺更硬）。若想彻底消除差异，只有两条路：① 自带一份楷体子集（通用 600 字约 300–400KB，全量 1.2MB 起）；② 保持现状接受回退。本版按你选的 ① 之外的折中做——**不引入字体文件，只把兜底从 SimSun 换成思源宋体**，缺字时字形更接近现代排版、不突兀。

**关于决策 3 的补充说明**：10 个页签用 `grid-template-columns: repeat(3, 1fr)` 排成 3+3+3+1，最后一行只有"静修"一格 —— 但它的宽度与其它格完全一致（`1fr` 均分），**不存在被拉伸或畸形**，只是视觉上右侧空两格。所以不改结构没有版面风险，这一点实测确认过。

## 1. 现状审计：七类问题，每条都有数字

### 1.1 字号：22 档，其中 10 档挤在 5px 区间内

实测 `font-size` 取值：

```
9  9.5  10  10.5  11  11.5  12  12.5  13  13.5  14  15  16  17  18  21  22  24  25  26  30  40
```

使用频次前六：`12px×20`、`11px×17`、`13px×14`、`10.5px×14`、`11.5px×11`、`10px×11`。

**问题**：9–13.5 之间有 **10 个档位、最小间距 0.5px**。半像素在 LCD 上会被取整成同尺寸，玩家看不出 10.5 和 11 的区别，等于这 5 个档位白设。反过来，写界面时每条信息都得临时决定用哪档 —— 这是界面层级混乱的**根因**，不是"不够精致"。

**证据**：修行图卡片里，"地图名 15px / 地名 10.5px / 描述 12px / 怪物名 10.5px / 难度章 10px / 状态 11px / 进入 11.5px"—— 同一张 240px 高的卡片里出现 **7 种字号**，玩家扫视时没有落点。

### 1.2 点击区：6 个可点控件，5 个低于 44px

实机量取（390×844，DPR2）：

| 控件 | 实测尺寸 | 达标（≥44×44） | 位置 |
|---|---|---|---|
| `.qb` 战斗快捷栏 | 46×46 | ✓ | HUD 右侧 |
| `#pauseBtn` 暂停 | 38×38 | ✗ | HUD 右上 |
| `.tab` 坊市买/卖页签 | 152×31 | ✗（高） | 坊市 |
| `.tab.mini` 坊市分类 | ≈148×26 | ✗（高） | 坊市 |
| `.sr-btn` 买入按钮 | 42×26 | ✗ | 坊市列表 |
| `.sr-btn.ghost` 洞府选择 | 38×25 | ✗ | 洞府 |
| `.chat-dove` 飞鸽 | 34×34 | ✗ | 战斗右下 |
| `.chat-emoji button` 表情 | 30×30 | ✗ | 聊天展开 |

**依据**：WCAG 2.5.5 Target Size 要求 44×44 CSS px；iOS HIG 44pt；Material 48dp。现金标准是 **44×44**。

**为什么这条排 P0**：坊市的买入/卖出按钮只有 26px 高，且"买入"和"卖出"两列紧邻（间距 4px）。玩家手指落点偏差 8px 就可能把"卖"点成"买" —— **误触直接亏资源**，这是运营事故级别的问题，不是审美问题。

### 1.3 垂直空间：4 个面板上下各空 250–300px

`#worldmap / #shop / #cave / #break` 都套用 `.overlay { justify-content: center }`。当内容量少于屏高时（坊市只有 2 件货、突破只有 3 行条件），面板悬浮在屏幕正中，**上方约 280px、下方约 280px 全空**。

实测：坊市面板高 ≈ 430px，屏高 844px，**空置率 49%**。

**问题不是"不好看"，是**：面板看上下不对称，玩家第一眼会找"是不是还有内容没加载出来"；同时内容多的时候（修行图 48 张图）又必须靠 `max-height: 92%` + 内部滚动硬压，同一套容器在两种极端下都别扭。

### 1.4 面板宽度：三套标准并存

| 容器 | 最大宽 | 用于 |
|---|---|---|
| `.panel` | 360 | 标题 / 暂停 / 结算 / 道陨 |
| `.wm-panel` | 460 | 修行图 / 坊市 / 洞府 / 突破 / 战前 / 联机 |
| `#dialogbox` | 440 | 剧情对话 |

在 390 宽屏上，`.overlay` 还有 24px padding，所以 `.wm-panel` 实际只有 **342px** —— `max-width: 460` 从未生效。三种宽度在切换界面时会产生**横向跳动**（342 → 360 → 342）。

### 1.5 小屏塞不下、大屏显小：字号不随屏变

因为 UI 用物理 px（见 §0），同一个 12px 正文：

- 375 宽小屏：占宽 3.2%，一屏能放的行数少，卡片被顶出滚动区
- 430 宽大屏：占宽 2.8%，文字偏小、留白偏多

实测对比：375×667 下修行图**第二张卡片已经贴到底部按钮**，只剩一条缝；390×844 下同一内容还有 200px 余量。当前没有任何断点或 `clamp()` 兜底。

### 1.6 层级：5 个孤立 z-index，其中 1 个是硬补丁

实测值：`2`（快捷栏键位号）、`25`（连斩）、`30`（拾取提示）、`46`（快捷栏）、`60`（聊天 / 全屏提示）。

**没有命名体系**，`46` 这个值来自上一轮修 bug —— 为了让"战斗中吃丹"点得到，把快捷栏从 6 一路提到 46 盖过对话层。这解决了一次问题，但下次再叠一层就会重演。层级必须一次定死并命名。

### 1.7 颜色与圆角：74 个色值、13 档圆角，无 token

- **色值 74 个 / 使用 203 次**。同一语义用了多个值：
  - "次要文字"：#9a927f、#8e9aad、#b9b2a0、#8f8878、#857d6d、#8b8474、#9a8a6a（**7 个**）
  - "金色强调"：#c9a24a、#ffd24a、#e0b24a、#c9912f、#d9a63c、#c9b27a、#e6cf94、#b99a55（**8 个**）
- **圆角 13 档**：3/4/5/6/7/8/9/10/12/14/16/17/999。同一个"卡片"在修行图是 12、在商店行是 9、在突破行是 8 —— 玩家感觉"每块都不太一样"，却说不出哪里不一样。
- **间距 20 档 padding + 10 档 gap**：`gap` 从 3 到 14 几乎每个整数都用过。

### 1.8 对比度：2 个灰阶不达 AA

按 WCAG 相对亮度算（背景取面板底 `#141823`）：

| 色值 | 用途 | 对比度 | 判定 |
|---|---|---|---|
| `#f2e8d5` | 主文字 | 13.9:1 | ✓ AAA |
| `#cfc6b2` | 正文 | 9.4:1 | ✓ AAA |
| `#9a927f` | 次要文字 | 5.9:1 | ✓ AA |
| `#8e9aad` | 说明 / 蓝灰 | 6.4:1 | ✓ AA |
| **`#7c7768`** | **禁用 / 弱提示** | **4.11:1** | ✗ 不达 AA |
| **`#857d6d`** | **空状态** | **4.5:1** | △ 临界 |

`#7c7768` 用在"暂无货物""未解锁""已用尽"这类关键状态上（`.mapcard.locked`、`.mc-state.off`、`.shopempty`），是全表最该看清的提示，却是对比度最低的一档。

### 1.9 HUD：生命/灵力条没有数值

战斗 HUD 的两条进度条只有 `生命`、`灵力` 两个标签，**不显示当前值/上限**。玩家无法判断"这一下能挨几下、这颗丹回了多少"，直接影响 §快捷栏吃药这类战斗决策。

### 1.10 列表底部渐隐裁切

`.wm-panel #wmList / #shopList / #victoryLoot` 用 `mask-image: linear-gradient(...)` 做底部渐隐。好处是暗示"还有内容"，坏处是**最后一项永远显示不全**，且"渐隐"和"禁用态变灰"在视觉上撞车（都变淡）。

## 2. 新规范

### 2.1 设计基准

| 项 | 规格 | 依据 |
|---|---|---|
| 世界层逻辑宽 | 480（不变） | 现有 `BASE_W` |
| 世界层逻辑高 | 864–1120 自适应（不变） | 现有 `resize()` |
| **UI 层基准宽** | **393**（Mate 60 Pro 的 CSS 视口），320–480 区间自适应 | 主力机型实测：1260×2720 物理 / DPR 3.5 → 393×852 |
| UI 基准单位 | **4px** | 2 的倍数在 DPR2/3/3.5 下均落在整像素 |
| 适配策略 | 面板宽度 `width:100%` + `max-width:460`，外层 `padding:16` → 实得 `min(100% - 32, 460)`；**不做小屏降档**（见 §2.9） | 393 上实得 361，宽屏封顶 460 |

> **v1.2 决策**：主力机型锁定 Mate 60 Pro（393×852），**原计划的 `max-width: 389px` 小屏降档方案作废**。
> 理由：为一台确定的主机做降档，等于让 95% 的使用场景为 5% 的极端情形让步；且 DPR 3.5 下
> 字号上调 1px 已被物理像素吸收，不存在"字太大"的问题。

### 2.2 栅格

**基准 4px，只允许以下 6 个间距档**（v1.2 已全表落地：padding 19 档 → 6 档、margin 13 档 → 5 档）：

| Token | 值 | 用途 |
|---|---|---|
| `s-1` | 4 | 图标与文字之间、标签内边距 |
| `s-2` | 8 | 列表行间距、卡片内 gap、相邻按钮间距 |
| `s-3` | 12 | 卡片内边距、区块内边距 |
| `s-4` | 16 | 面板内边距、区块间距 |
| `s-5` | 24 | 大区块间距、单段式面板内边距 |
| `s-6` | 32 | 屏级留白、空态上下留白 |

**徽章类（chip / badge）例外**：垂直 padding 归 0，高度交给 `line-height`。理由——徽章的"内边距"本质是行高，
用 padding 撑会让它在密集列表里忽胖忽瘦；改用行高后，同一行里所有徽章的基线与高度自动对齐。
落地：`.mc-tag` 等用 `padding: 0 var(--sp-2); line-height: 1.6`，`.mat` / `.dc-tag` 等用 `padding: 0 var(--sp-1)`。

**列栅格**

- 2 列（属性/装备格）：等宽，`gap: 8`，列宽 `calc((100% - 8px) / 2)`
- 3 列（页签/难度章）：等宽，`gap: 8`
- 页签数量必须是 2/3/4/6 的整数倍 —— 现有 10 个页签排 3 列会剩 1 个孤格（实测洞府即如此），改 2 列或分组（见 §4 P1-6）

**内容左边距统一 16**：现在修行图是"面板 padding 14 + 卡片 padding 10 = 24"，坊市是"14 + 9 = 23"，突破是"20"。三者文字左边界差 4px，翻页时眼睛能捕捉到跳动。统一为 16。

### 2.3 安全区（三层）

| 层 | 值 | 实现位置 | 说明 |
|---|---|---|---|
| L1 设备安全区 | `env(safe-area-inset-*)` | `#wrap` padding（现有，保留） | 刘海 47px / 底部 34px（iPhone 14） |
| L2 舞台边距 | **12** | HUD 元素距舞台边 | 血条、暂停键、技能栏、快捷栏 |
| L3 内容边距 | **16（窄）/ 24（宽）** | 面板内 padding | 面板 ≥ 400 宽时用 24 |

**底部交互区硬性要求**：技能栏 / 快捷栏 / 鸽子按钮距舞台底边 **≥ 12px**，且不得与 L1 重叠（L1 已把 stage 内缩，但 L2 仍需保留，防止误触系统手势区）。
现状 `#skillrow { bottom: 10px }`、`.chat-wrap { bottom: 14px }` —— 前者改 12，后者对齐 12。

### 2.4 字号阶梯（6 档）

| 档位 | 字号 | 行高 | 字重 | 用途 | 对应现有 |
|---|---|---|---|---|---|
| `t-display` | 32 | 1.2 | 700 | 游戏标题 | 40 → 32 |
| `t-h1` | 24 | 1.3 | 700 | 面板标题（修行图/坊市/洞府/突破/暂停/结算） | 22、24、26 → 24 |
| `t-h2` | 17 | 1.35 | 600 | 区块标题、卡片名、对话说话人 | 15、16、17 → 17 |
| `t-body` | 15 | 1.6 | 400 | 正文、对话内容、按钮主文案 | 13、14、15 → 15 |
| `t-cap` | 13 | 1.5 | 400 | 次要说明、列表描述、页签、次按钮 | 11.5、12、12.5、13 → 13 |
| `t-micro` | 11 | 1.4 | 400 | 标签、角标、单位、难度章、键位号 | 9、9.5、10、10.5、11 → 11 |

**收敛对照**：22 档 → **6 档**。被合并的 16 个值：9、9.5、10、10.5、11.5、12、12.5、13.5、14、16、18、21、22、25、26、30。

**例外（允许单独定，但需在代码里注释原因）**：

| 场景 | 字号 | 理由 |
|---|---|---|
| 战斗连斩数字 | 32 / `tabular-nums` | 瞬时反馈，必须一眼扫到 |
| HUD 数值（生命/灵力/灵石） | 12 / `tabular-nums` | 等宽数字防跳动；12 是因为 HUD 空间只有 40px 高 |
| 卡片内"地名"这类弱标注 | 11（`t-micro`）+ 字距 0.5px | 不再单独开 10.5 |

**行高为什么这样取**：正文 1.6 是中文长文可读性下限（`desc` 现在就是 1.7，保留）；标签类 1.4 避免单行占高过多；标题 1.2–1.35 让多行标题不散。

| 元素 | 按下 | 禁用 | 选中 | 备注 |

| 地图卡 `.mapcard` | ✓ | ✓ `.locked` | ✓ `.current` | |

| 功法折叠头 `.pf-tier-hd` | ✓ | — | ✓ `.open` / `.cur` | v1.3 补按下+悬停 |

**按下幅度分三档，按元素面积定**（不是为了统一而统一）：

| Token | 值 | 用在哪 | 依据 |
|---|---|---|---|
| `--press-sm` | 0.94 | 圆形小钮 ≤46px（快捷栏 / 飞鸽 / 表情） | 面积小，缩得多才看得出 |
| `--press` | 0.97 | 一般按钮、列表行、装备格 | |
| `--press-lg` | 0.99 | 整行卡片（地图 / 难度） | 面积大，缩多了像在晃 |

**反馈语言也分三种，各归其位**：

1. **位移 + 投影**（`.btn`）：`translateY(2px)` 且投影从 4px 收到 2px —— 模拟按钮被按进去，适合有立体感的实体按钮。
2. **缩放**（卡片 / 行 / 圆钮）：只改 `transform`，不动颜色。
3. **提亮**（`.sr-btn`）：`filter: brightness(1.18)`。彩色按钮（金底「买入」）不能换背景色 —— 一换就把渐变打断，按钮看起来像变成了另一颗。

**禁用统一 `.45`**（`--op-disabled`）：原来 `.4` / `.42` / `.45` / `.55` 四种值混用，统一后玩家不会觉得"同样不能点，怎么有的更灰"。

**状态叠加必须排除自身**：`.tab:active` 会把已选中的金底打回灰底，必须写 `.tab:active:not(.active)`。这类"两个状态打架"的问题只闪一帧，截图几乎抓不到 —— 靠守门测试按住鼠标读 computed 值才能验。

**命中区扩展的实测坑（重要）**：视觉高度靠 `::after { inset: -Npx 0 }` 补命中，但 **N 不能用"目标 − 视觉"算出来的理论值**。列表按钮视觉 36、目标 44，理论该扩 4；实测用 `elementFromPoint` 逐像素探，只扩出 3/2px（合计 41）—— 边界像素取整会吃掉一部分。改成 6 后实测 5/4（合计 45）才达标。**规矩：扩完必须实测，不能算完就交。**

扩命中区还有两个副作用，必须一起处理：

- **同组内换行会重叠**：`.sr-btn` 扩 6，`.sr-btns` 行间距就必须 ≥12（原 8 → 12）；表情按钮扩 6，`.chat-emoji` 的 `row-gap` 也必须 ≥12（原 4 → 12）。否则点上一排的下缘会触发下一排 —— 卖出行就是「卖 / 卖尽 / 拆 / 拆尽」四颗挤一处。
- **水平方向不要扩**：`inset: -6px 0` 的左右保持 0，靠容器 `gap ≥ 8` 隔开。水平扩会让「卖」和「卖尽」互相侵入，那是真亏资源的误触。

### 2.11 动效（v1.5 新增）

**改造前**：8 个时长值散在各处 —— `.1s` / `.12s` / `.15s` / `.16s` / `.18s` / `.22s` / `.26s` / `.3s`；
缓动只有 `linear`（血条）、`ease-out`（两处）和一堆**浏览器默认的 `ease`**（其余全部）。
落到玩家手上就是：同样都是"按下去"，卡片反应比按钮快一点、页签又慢一点；血条缩得慢、boss 血条更慢。

**时长按「眼睛要多久才跟得上」定，不按「想快想慢」定**：

| Token | 值 | 用在哪 | 依据 |
|---|---|---|---|
| `--dur-press` | 90ms | 所有按下反馈（transform / filter / 位移） | 手指落下到看见反馈超过 100ms 就开始发肉，这是手感底线 |
| `--dur-hover` | 140ms | 悬停、边框色、背景色、页签切换 | 颜色比形变更能容忍时间；140ms 刚好读得出"在变"又不拖 |
| `--dur-move` | 200ms | 位置位移、展开折叠、输入框伸缩、拾取提示上浮 | 位置移动要被眼睛追踪，低于 150ms 会看不清从哪来 |
| `--dur-pop` | 280ms | 强调动画（连斩弹出） | 需要一点"呼吸"；再长就显得卡 |
| `--dur-bar` | 120ms | 血条 / 灵力条 / boss 血条 | 单独一档：跟随连续数值，太快会抖、太慢会糊成一片 |

| Token | 值 | 依据 |
|---|---|---|
| `--ease-press` | `cubic-bezier(.2,.7,.3,1)` | 快起微收，有回弹感但不弹过头 |
| `--ease-out` | `cubic-bezier(.22,1,.36,1)` | 出场与位移：快起慢收 |
| `--ease-inout` | `cubic-bezier(.4,0,.2,1)` | 展开/折叠这类双向变化，两端对称 |
| `--ease-bar` | `linear` | **数值条必须匀速** —— 血量掉一半就该用一半时间，用缓动会看成"先掉快后掉慢" |

**按下必须补过渡，不是"有 :active 就够了"**。改造前 `.btn` / `#pauseBtn` / `.qb` / `#dialogbox` / `.deck-toggle` / `.chat-emoji button` 六处按下是**瞬跳**：按下瞬间到位、松手瞬间弹回，视觉上像硬切。补 `--dur-press` 后，按下仍然立刻响应（90ms 感知不到延迟），松手才有回弹。

**无障碍**：末尾加 `prefers-reduced-motion: reduce`，把 `transition-duration` / `animation-duration` 统一压到 `1ms`。注意不是"关掉反馈"—— 颜色与位移变化仍在，只是不再"动"；血条也一起压，这类用户看到数值缓慢爬动会不适。

### 2.12 横幅落点：按 HUD 在不在分两套（v1.5 新增）

**问题**：`#banner` 固定 `top: 152px`。152 这个数是给**战斗 HUD** 让位的（顶栏约 86，boss 血条下沿 133）。但坊市、洞府、修行图里 HUD 是隐藏的，152 就变成了**砸在面板上部**——坊市里正好压住页签，横幅挂 2.2 秒，这 2.2 秒里玩家看不见自己在点哪。

**做法：不按状态名枚举，按 HUD 是否真的可见来判断。**

| 场景 | 落点 | 依据（393×852 实测） |
|---|---|---|
| 战斗态（HUD 可见） | 152 | HUD 最低下沿是 boss 血条 133，留 19px |
| 面板态（HUD 隐藏） | 16 | 横幅高 37，面板上沿 66，余 13px |

**为什么取 16 而不是 24**：24 只剩 5px 余量，文字里带 emoji 就会撑高到 40+ 直接压上面板。16 留 13px，撑到 46 也不压。

**判定必须用真实可见性**：`#hud` 的隐藏写在 CSS 里，`elHud.style.display` 是**空字符串**，拿 `'' !== 'none'` 去比会恒为真 —— 等于永远走战斗态。要用 `elHud.getClientRects().length`。这个坑已经实际踩过一次。

**坐标系别想当然**：`#stage` 的尺寸是 `resize()` 动态算出来的（`H = clamp(864, 480 × 视口宽高比, 1120)`，再整体缩放），**不是 CSS 里写的 480×864**。所以 `#banner` 的 `top` 是真实 CSS px，面板上沿 = `(视口高 − min(视口高−32, 720)) / 2`。

**已知边界**：375×667 这类矮屏面板上沿只有 16，横幅必然压面板。主力机型 852，不为小屏改。

### 2.13 图标位：固定宽度槽（v1.5 新增）

**先说清楚对象**：`js/sprites.js` 里**没有图标** —— 那是 30 个角色/怪物/景物精灵（韩立、狼妖、古树、灵石…）。物品图标与功法图标是 **emoji 字符**，由系统字体渲染。所以"统一线宽"这件事在 emoji 上做不到（笔形是字体厂商定的），能做的是**统一占位**。

**实测数据**（同为 17px 字号，墨迹宽 = `measureText` 的 actualBoundingBox）：

| 项 | 值 |
|---|---|
| 平均墨迹宽 | 16.7px |
| 最宽 | 🗺 24px（1.41 倍字号） |
| 最窄 | 🗡 9px（0.53 倍字号） |
| 极差 | **2.67 倍** |

换算到列表正文 13px，就是 **6.9 ~ 18.4px**。不固定宽度时，同一列里每一行的名字左边缘会差出近一个字符 —— 整列看着是斜的。

**规格**：

```css
.ico { display: inline-block; width: 1.5em; text-align: center; font-style: normal; }
```

1.5em @13px = 19.5px，装得下最宽的 18.4。JS 侧统一走 `ico(x)` 辅助函数包裹，**不要再手拼 `icon + ' ' + name`**。

**已落地**：洞府 5 处列表行（升级选择、功法、灵宠蛋、灵宠、同伴）。同伴页 4 行实测名字起点全部 61.5px —— 唯一值，完全对齐。

**图标家族审计**（99 个去重图标 / 149 个注册点）另见 `凡人长生劫-图标家族表.md`：9 个纯色几何块混在其余线描 emoji 里、34 组跨类共用、6 组同物不同图标、`📕` 被 21 本不同法诀共用。

**v1.3 的方法论收获（三次都是"算对了但实测不对"）**

1. **命中区不能靠算**：理论 44 减去视觉 36 等于扩 4，实测只有 41。边界像素取整会吃掉 1–2px，必须逐像素探 `elementFromPoint` 才是真值。
2. **`renderShop()` 会重建 DOM**：在循环里缓存按钮句柄再逐个点，第二次起全点在已脱离文档的节点上，静默失效。测试里每轮必须重新查询。
3. **按下反馈不只有 transform**：`.sr-btn` 用 `filter`，如果只比 `transform` 会误判"没有按下态"。要比 `transform + filter + background` 的组合。

**v1.4 的方法论收获（三处"点了没反应"，根因三层，一层比一层深）**

1. **先看"有没有反馈"，再看"反馈是什么"**：玩家说"点不动"，实际可能是事件没绑、可能是 `disabled` 吞掉事件、也可能是提示弹了但被面板盖住。三层要分别验：真实点击 → 读状态变化 → 读横幅 computed z-index。只测第一层会漏掉后两层。
2. **`disabled` 是"说不出理由"的开关**：代码里明明写好了「灵石不足 · 还差 N」，但按钮一 `disabled`，浏览器根本不发事件，那三句提示全成死代码。凡是要"点了告诉用户为什么"的按钮，都不能用 `disabled`。
3. **`aria-disabled` 不是 `disabled` 的样式替代品**：它的语义就是"这个控件不可操作"，与"点了要能解释"自相矛盾 —— 连 Playwright 都会拒绝点击它。只表达样式就用自定义属性（`data-cant`）。
4. **事件委托里，按钮必须排在整行之前判**：`closest('[data-equip]')` 会从按钮一路向上找到整行。修完还要加第二道防线 `&& !e.target.closest('button')`，否则以后再加个按钮又踩同一个坑。

node qa/verify-shop-cave.mjs    # 38 项：拆解走对分支 / 功法购买不再静默 / 横幅压过面板 / 空态
node qa/shot-ui-audit.mjs       # 出各界面截图 + 元素尺寸
node qa/measure-panels.mjs      # 面板几何：宽 / 高 / 上距 / 下距 / 空置率
node qa/shot-hud.mjs            # HUD 顶栏与暂停键局部放大（6x）

`verify-ui-spec.mjs` 的做法（不是读 CSS 源码，是量真实渲染）：

1. **字号**：遍历所有可见且有文字的元素，`getComputedStyle().fontSize` 必须落在 `{11,12,13,15,17,20,24,32}`；12 与 20 是注明例外。
2. **命中区**：从元素中心向上下逐像素探 `document.elementFromPoint`，直到探不到该元素为止 —— `::after` 扩出来的命中区会被算进去，所以量的是**玩家真实能点到的范围**，不是视觉尺寸。
3. **间距**：读相邻按钮 rect 求间距，断言 ≥8。
4. **对比度**：把 token 解析成 rgb 后按 WCAG 相对亮度算，断言 ≥4.5:1。
5. **层级**：断言 `panel < dialog < combat < modal`，且快捷栏实际 z 值等于 `z-combat`。
6. **变量健全**：token 都有值、值里不能再出现 `var(`（自引用会整块失效，这条是真踩过的坑）。
7. **间距体系**（v1.2 新增）：扫 CSS 源码里所有 padding / margin 数值，每个都必须落在 `{0,4,8,12,16,24,32}`，且档位总数 ≤6。
8. **面板几何**（v1.2 新增）：依次打开标题 / 修行图 / 坊市 / 洞府，断言四者**同宽**、三个列表面板**同高**、列表面板占屏 ≥70%。
9. **HUD 与标题统计**（v1.2 新增）：`#hpval` / `#xpval` 必须匹配 `数字/数字`、`font-variant-numeric` 为 `tabular-nums`、字号 12px；标题页两处统计的 `.ts-row` 数量 ≥4 / ≥7，每行必须是「字段名 + 数值」两段，且不再出现「·」串联长句。
10. **状态矩阵**（v1.3 新增）：对暂停键 / 地图卡 / 列表按钮 / 装备格 / 装备行五处，**真的按下鼠标**（`mouse.down()`）再读 computed 值，断言与常态不同 —— 不是 grep `:active` 有没有写。另外断言买不起的货挂的是 `.poor`（走整行降透明度）且按钮**不是 `disabled`**（v1.4 调整，见下条）、已选中的页签按住时不闪回灰底。
11. **「能不能点」与「点了说什么」分离**（v1.4 新增）：`disabled` 是"浏览器不发事件"，`aria-disabled` 是"无障碍语义上不可操作"，两者都会让按钮**说不出理由**。买不起 / 境界不够 / 已学过三种情况统一由 `buyItem` 用横幅讲清差多少 —— 所以按钮只挂 `data-cant` 表达样式，绝不挂 `disabled` / `aria-disabled`。

`verify-buttons.mjs` 的做法（v1.3 新增，62 项）：

全部走 `locator.click()` 与 `mouse.click(x, y)`，不调调试接口抄近路。每项断言的都不是"点了没报错"，而是**状态真的变了**：灵石减少、袋中 +1、`save.equip` 多了一项、`G.state` 变成 pause、`save.quick[0]` 真的是那味丹。命中区那一组先在边界外点击确认**仍命中**，再在外 12px 点击确认**不命中**，两头都验才说明扩展区既有效又不过界。

`verify-shop-cave.mjs` 的做法（v1.4 新增，38 项）：

专治"按钮看得见、点下去没动静"。三组：

1. **拆解走对分支**：造两件同名兵器、佩上一件，点行内「拆」→ 断言袋中 2→1、材料进袋、身上那件还在；再点行体确认**仍能佩上**（修委托顺序不能把整行点击弄坏）；只剩身上那一件时「拆」按钮必须收起。
2. **买不起要说得出理由**：灵石 0 点功法 → 断言横幅出现且含「灵石不足 · 还差 N」、灵石不动、功法没入册；钱够但境界不够 → 「境界不足 · 需 X」；境界够钱够 → 真买到且扣款正确；已学过 → 按钮标「已学」、再点只提示不扣钱。
3. **横幅压过面板**：断言 `z-banner > z-panel`、`pointer-events` 为 `none`，并实测**横幅正挂着时**再点一次货架按钮仍有反馈（证明它没挡住点击）。

**没做（下一轮候选）**

1. **图标内容替换**：§2.13 只解决了「占位一致」（图标位），没动图标本身。9 个纯色几何块、
   34 组跨类共用、`📕` 被 21 本法诀共用 —— 这三项都要拍板才算数，清单与优先级见
   `凡人长生劫-图标家族表.md` §6。**换一个 emoji 就是改玩家的视觉记忆，属内容决策，我不擅自改。**
2. **emoji 跨设备不一致**：华为用 Noto、iOS 用 Apple、Windows 用 Segoe，同一套代码图标长相完全不同。
   唯一的根治办法是自绘像素图标（`sprites.js` 已证明这条路能走通），属独立立项。
3. **宽屏（≥ 600）未验证**：面板封顶 460，但 HUD 在平板/桌面上会拉得很开，血条能到 900px 宽，数值分隔过远。主力机型是手机，暂不处理。
4. **矮屏（375×667）横幅会压面板**：面板上沿仅 16，横幅高 37，无处可让。按决策"不为小屏改"搁置。
5. **面板出现/消失无动画**：现在靠 `display` 切换，是瞬现。加入场动画会拖慢操作感知，且 `display` 过渡需要改结构，本轮不动。
6. **坊市货架 / 储物袋的图标位未统一**：`ico()` 只接进了洞府 5 处列表，坊市 `.sr-main b` 与储物袋仍是手拼。列对齐问题在这两处同样存在。
7. **丹药柜只有 1–2 件货**：定高面板下留白偏大，属内容侧（要不要上架基础丹）而非版式问题。

**按规格不做**

- **不出高保真视觉稿**：本作界面是"DOM + Canvas 像素风"，重画 PNG 稿无法落地，规范和 token 才是可直接施工的东西。
- **不统一 emoji 的笔画线宽**：笔形由字体厂商决定，CSS 改不了。规格只统一占位与尺寸，不假装能统一笔画。
- **不动世界层（Canvas）内的战斗表现**：伤害数字、连击特效属于画面层，不在版面规范范围。
- **不改洞府的 10 页签结构**：按决策 3 保持现状。
- **不做小屏降档**：按 v1.2 决策，主力机型为 Mate 60 Pro（393×852），不为更小屏牺牲主场景的字号。
