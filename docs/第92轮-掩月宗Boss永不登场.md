# 第92轮 · 掩月宗 Boss 永不登场（bossAt 缺省）

**版本** `20261104S`　**起因** Jerry 实测反馈：掩月宗打了 10 分 32 秒，Boss 一直不出来。

---

## 一、现象

截图里：小怪滚滚来（斩 3157 刀、元婴后期·圆满），场上一波接一波远程弹幕，但**从头到尾没有 Boss**，也没有任何「妖气逼近」的预警。玩家只能一直清小怪，这张图无法通关。

---

## 二、根因

一句话：**`bossAt: 0` 撞上了 `if (at > 0)`。**

`js/game.js` 的 Boss 登场调度只有一条时钟判据：

```js
const at = G.map.bossAt || 0;
if (at > 0 && G.time >= at - 3 && !G.bossWarned) { ...预警... }
if (at > 0 && G.time >= at) spawnBoss();
```

`at` 取不到值时恒为 `0`，而条件是 `at > 0` —— **0 恰好落在「永不成立」这一侧**。于是：

- 预警不播（同样卡在 `at > 0`）
- `spawnBoss()` 永不调用
- `G.bossSpawned` 永远为 false → `spawnDirector` 继续无限刷小怪

整张图变成一个没有终点的清怪场，而且**没有任何报错、没有任何日志**。

### 为什么只有掩月宗这一张

`type: 'boss'` 的剧情战不吃这条时钟判据：它在开场剧情回调里直接 `spawnBoss()`（`game.js` 里那句 `if (m.type === 'boss') spawnBoss();`），`bossAt` 写 0 完全没事。

真正依赖 `bossAt` 的是 `type: 'combat'` 的战斗图。全量体检结果：

| type | 可刷出 | 说明 |
|---|---|---|
| `boss` | 59 / 59 | 开场即 Boss，不看 `bossAt` |
| `combat` | **21 / 22** | 21 张都写了 `bossAt`（90~150s） |
| 合计 | **80 / 81** | 唯一漏网的：**`yanyue` 掩月宗** |

`yanyue` 是全表唯一一张「`combat` 类型 + 有 Boss + `bossAt` 写 0」的图。相邻的苍坤洞府是 120、阴罗宗是 130 —— 它应该是排版时漏填了。

## 三、改法（两层）

### 1. 数据：补回真实时点

```js
// js/late2.js · yanyue
diff: 2.7, bossAt: 120, intro: 'yanyue', outro: 'yanyue_out',
```

取 120s，与前后两张同章节战斗图（苍坤 120、阴罗宗 130）一致。

### 2. 代码：兜底，让「漏填」不再等于「永远不刷」

只补数据的话，下一张新图漏填还会再犯一次，而且**同样是静默的**。所以在调度处加了兜底：

```js
// type:'boss' 不吃这条 —— 它是开场回调里直接 spawnBoss()，不靠时钟
const at = (G.map.bossAt > 0) ? G.map.bossAt
  : (G.map.type !== 'boss' ? 120 : 0);
```

口径变成 **「有 Boss 配置的战斗图，一定会来」**：

- 写了 `bossAt` → 按写的来，行为完全不变
- 漏填/写 0 → 120s 登场（和绝大多数战斗图同一档）
- `type:'boss'` → 仍走开场回调，不受影响

## 五、一个值得记的教训

**「缺省值落在判断条件的死侧」是很容易复发的坑。**

`|| 0` 把「没填」和「填了 0」压成同一个值，而判据是 `> 0` —— 两者一起构成一个静默的死分支。这类 bug 的特征是：

- 不报错、不崩、不影响性能
- 症状是「某件事永远不发生」，而不是「发生错误」
- 只有在**玩家真的把那张图打到 10 分钟**时才会被发现

同类风险点已检查：`escapeAt`（追逃图脱身）也是 `G.map.escapeAt && G.time >= ...` 的写法，但追逃图必然带 `escapeAt`（否则这张图本身无解），暂不需要兜底。
