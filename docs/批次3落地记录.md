## 一、核心问题：贴图式地形怎么「既水墨、又不卡」

这是 Jerry 本轮点名的问题。先给路线判断（动手前的硬闸门）：**这个游戏不能做「真贴图」，也不该做「瓦片」**。

- 现状是 480×H **无限滚动割草场地**：没有瓦片、没有世界边界、没有地形数据；171 张图的地面、装饰、视差全是 `game.js` 里**程序化画的**，精灵走 `inkSprite()` / `SKIN_INK` Proxy 整体墨化，**没有美术资源管线**。
- 报告第 17 / 125 行已明确否掉 16 掩码 Wang 集 / Tiled 路线（要重做世界坐标与刷怪，收益风险不匹配）。

| 候选路线 | 水墨风格 | 流畅度 | 判定 |
|---|---|---|---|
| 真 PNG 贴图 / 逐格瓦片 / Wang 集 | ❌ 硬边方块，跟现有程序化笔法 + inkify 打架，必然一地马赛克 | ❌ 每屏几千次 `drawImage` + 图片解码 | **否** |
| 每帧程序化重画地形（渐变/路径/brush） | ✅ 笔法一致 | ❌ 每帧重算 `radialGradient` + 多笔路径，满屏特效时叠加吃满帧预算 | 否 |
| **离屏预烘焙 + 缓存 + 每帧 1 次绘制** | ✅ 复用现有 `brush/cun/bank/stone` 同源笔法 | ✅ 进图烘一次，每帧只 +1 次 `fillRect`/`drawImage` | **采用** |

**正解 = 程序化离屏烘焙的软边贴地明度块 + 一次缓存 + 每帧 1 次绘制。** 三个附带好处：

1. **零美术工作量**：同一套程序化笔法按 biome 参数化覆盖全部 171 张图，化解报告「工作量按图线性增长」「笔法一致性」两个担忧；
2. **零加载 / 零网络**：全部离屏 canvas，不引外部 PNG；
3. **换皮自动生效**：按 `skin/W/H/biome` 缓存，切皮时缓存失效重建（沿用批次2 `pxCache` 纪律）。

### 分层与每帧开销（关键）

```
屏幕固定：grassPat(1) + 视差 far/mid/near(3) + frame(1)
   └ translate(-cam)
世界 1:1：grain(1) ＋ [P1-4 贴地层 1×fillRect] ＋ [P1-2 地标 1~3×drawImage] ＋ decor(N) ＋ 特效/角色(原有)
判定：G.zones / G.hazards  ——  完全不碰
```

- **空间记忆由 P1-2 地标承担**（世界坐标固定、每图 1~3、不重复）；**贴地层只管柔化地面**（纹理级、软边低对比、平铺不易察觉）。两者分工，正好绕开「瓦片化」被否的坑。
- 贴地层复用 `px.grain` 同款 `createPattern` + 每帧 1 次 `fillRect(G.cam.x, G.cam.y, W, H)`，世界坐标锚定、随相机 1:1 走；挂进 `buildGrass()`，一条路径覆盖进图 / 换皮 / resize 三条重铺。

## 二、三项改动与口径

| 项 | 改动 | 涉及文件 | 口径 |
|---|---|---|---|
| **P1-2** L2 地标 | 按 `map.id` 确定性 hash 生成 1~3 个世界坐标固定地标（山门 / 断碑 / 枯井 / 骨堆 / 石阶 / 幡杆 / 大石灯，按 biome 选），88×92 离屏烘焙 | `js/game.js`（`sc3Bake` 大画布 case、`sc3DrawLandmarks`） | 明度 0.45（报告 L2 口径 0.55 再收一档）、软边洇染；画在 `drawDecor` 之后、地面特效**之下**，`verify-hazards` 满屏特效下不被盖；不参与碰撞 |
| **P1-3** biome 装饰包 | 原 `tree/rock/tuft` 3 种 → **12 种**（+竹/松/苔石/水洼/云气/残垣/石灯/经幡/骨殖）；`arc` A~M 归 **6 组 biome**，每组一张权重表 | `js/game.js`（`SC3_TYPES` / `SC3_BIOME` / `sc3Bake` 小画布 case / `genChunk` scheme 覆盖） | 单件 40×48，`genChunk` 每 chunk 6 件密度**不变**只换类型（CPU 不增）；新类型走 `blitSprOn` 局部精灵表，原 3 种仍走 `window.Sprites` 老路径 |
| **P1-4** 贴地明度块 | 浅水 / 石阶 / 云海 / 断崖 4 类软边明度块，`radialGradient` 洇染，3×3 偏移保证无缝平铺；四角摆块、中央留白 | `js/game.js`（`sc3BakeTerrain` / `ensureScenery3` / `render`） | **纯视觉**，不写入 `G.zones`，不加减速、不改可行走性；软边渐变非硬边矩形 |

### 关键工程取舍

- **一个自包含模块 + 一个统一懒缓存 `ensureScenery3()`**：按 `skin|W|H|biome|mapId` 缓存，换皮 / resize / 进图自动失效重建；全项目只改 4 个调用点（`render` / `genChunk` / `drawDecor` / `__FR`）。
- **样板期白名单 `SCENERY_SAMPLE = new Set(['houshan'])`**：非白名单 170 张图 `ensureScenery3()` 直接短路返回 `{on:false}`，scheme / 绘制走原逻辑，**逐字节不变**，回归零风险。下一轮全量只需把白名单换成「按 biome 恒启用」。
- **smoke 垫片安全降级**：所有 `createElement('canvas')` / `getContext` / `createRadialGradient` 均做能力探测，垫片（无真实像素 API）返回 null，不注入也不绘制 → smoke 294 全绿。
- **不碰 `window.Sprites`**：新精灵存局部 `sc3.spr` 表，避免污染批次1/2 的墨化 Proxy 与相关断言。

## 三、六查：亲眼看出问题并修掉（本轮最有价值的一步）

首版实拍 `shot-scenery3-guigu-on.png` **亲眼复看**发现两个风格违规，结构校验全绿但画面不对，正是「结构通过 ≠ 能用」：

1. **竹子画成「井字栅栏」** —— 3 根直竿 + 横节 + 对称斜叶，笔直交叉成硬边网格；
2. **地标是硬边灰方块** —— 断碑/石阶边缘笔直、明度太实，像贴了补丁。

对照 `shot-scenery3-guigu-off.png`（关三层）确认：off 画面干净只有小树/草丛/石头，这些硬边图形确实是批次3 新增。另发现鎏金皮也是浅纸底 —— 对比 `shot-parallax-jin.png`（批次2）确认为**批次1 墨阶改造后 `buildGrass` 优先取 `m.inkBg` 的既有现象**，非本轮引入，不越界修改。

**修复（4 处）**：

| 修复 | 做法 |
|---|---|
| 竹子/松树重写 | 竹改「略带弧度的 `quadraticCurveTo` 竿 + 点叶簇」，不画横节/对称斜叶；松改「斜干 + 点叶墨团」，不画横展针线 |
| 软边淡出罩 | 每个新精灵烘焙末尾加 `destination-in` 径向渐变，四周 alpha 渐隐到 0，像墨洇进宣纸 —— **这是「不像硬边贴片 / 不马赛克」的关键** |
| 调色 | 两皮统一淡墨灰阶（金皮略暖），不用近黑暗金（浅纸底上会显脏）；整体 alpha 再压一档（`×0.72`），装饰/地标退到纸后面（第83轮 L1/L2 口径） |
| 地标明度 | 0.55 → 0.45，不与主角抢视线 |

复看 `shot-scenery3-guigu-on.png` / `shot-scenery3-jin-on.png`（修复后）：井字栅栏消失、断碑/石阶洇进纸里、无彩色无脏块、中央留白与主角清晰、双皮风格统一。

{"w":480,"h":900,"nonZero":63663,"maxAlpha":33,"solidPixels":0,"distinctAlpha":34}
