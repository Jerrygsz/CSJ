## 0. 先纠正一个前提

这一轮原本的立项前提是「`sprites.js` 里技能图标和物品图标没有统一的线宽/留白率」。

**核实结果：`sprites.js` 里一个图标都没有。** 那 280 行是 30 个**角色 / 怪物 / 景物**精灵，用字符网格 + 调色板画的：韩立、狼妖、鬼灵门王蝉、古树、岩石、灵石、飞鸽。它们有明确统一的规格（通用描边色 `#1b1b2a`、人物 12×14 格、四档袍色随境界）。

**物品图标与功法图标是 emoji 字符**，由系统字体渲染，散在 `items.js` / `late*.js` / `skills.js` 的 `icon` 字段里。

所以「统一线宽」这件事在 emoji 上**做不到** —— 笔形、粗细、圆角都是字体厂商定的，我们改不了笔画。能做的是三件事：**统一占位**、**消除家族异类**、**消除语义撞车**。这三件才是真问题，而且比原设想严重。

## 2. 四类问题，逐条有清单

### A. 同一样东西两副面孔（6 组）

同一个实体在不同文件里被给了不同图标 —— 玩家在坊市看到的样子，和在洞府/修行图看到的不一样。

| 实体 | 图标 A | 图标 B |
|---|---|---|
| 五子同心魔 | `👁`（skills.js 功法） | `👥`（late2.js 同伴） |
| 大衍诀·后三层 | `📗`（skills.js 法诀） | `📘`（late2.js） |
| 大衍诀 | `📘`（skills.js） | `📘`（late.js）→ 与上一行同图标但一个是全本一个是后三层 |

> 说明：确认这 6 组要逐个查来源，其中「同物」与「同族不同物」需要分开处理，不能一律统一。

### B. 跨类别共用同一图标（34 组，最伤辨识）

同一个图标同时代表两个**完全不同类别**的东西。这是图标家族最严重的问题 —— 图标本该帮玩家分类，结果它在跨界。

最典型的几组：

| 图标 | 被谁共用 | 问题 |
|---|---|---|
| `🛡` | 装备槽·护甲 / 装备·护身玉符 / **道具·避尘符** / 功法·金光罩 | 一张符箓用盾牌，类别错 |
| `📕` | **道具·破禁符 + 21 本不同法诀** | 见 D 节，最严重 |
| `🗡` | 装备·精铁短剑 / 玄铁重剑 / 血魔剑 / 功法·控物术 / 功法·大庚剑阵 | 兵器与功法撞 |
| `⚔` | 装备槽·兵器 / 装备·青竹剑 / 青竹蜂云剑 / 功法·青元剑诀 | 同上 |
| `🌀` | 道具·空间传送符 / 装备·风刃符宝 / 功法·破界符 | |
| `🐉` | 装备·蛟龙甲 / 灵宠·墨蛟 | 一件甲与一只宠长一样 |
| `🐛` | 装备·噬金虫袋 / 灵宠·噬金虫 | 袋子与虫长一样 |
| `💍` | 装备·阳环 / 道具·灵兽环 | |
| `🔮` | 装备槽·佩饰 / 装备·聚灵珠 | 槽位与物品撞 |
| `🌙` | 装备·银月 / 灵宠·银月 | 这个其实是同一角色（器灵本体 + 灵宠形态），**可保留** |
| `🌌` / `🪽` / `🪭` / `🔱` / `💀` / `❄` / `📗` / `📘` / `🍶` / `🤖` | 各 2–3 个跨类实体 | 详见脚本输出 |

**判断标准**：同类别内共用（两把都是剑）可以接受，那是"族徽"；**跨类别共用一律要拆**，因为玩家是靠图标先分类、再看文字的。

### C. 纯色几何块：9 个家族异类

| 图标 | 用途 |
|---|---|
| `🔴` | 道具·止血丹 / 魔元丹 |
| `🟠` | 道具·疗元丹 / 降尘丹 / 造化丹 |
| `🟡` | 道具·黄龙丹 / 补天丹 |
| `🟢` | 材料·蛇胆 / 定灵玉 |
| `🟣` | 道具·筑基丹 / 装备·天雷子 |
| `🟤` | 材料·赤铜 / 道具·金髓丸 |
| `⚪` | 装备·玄玉珠 / 材料·尸傀骨粉 / 罡银沙 |
| `⬛` | 材料·玄铁 |
| `💠` | 材料·玉髓 |

这 9 个是**实心圆 / 实心方块**，其余 90 个是有细节的线描或写实图形。放在同一列里，它们视觉重量最大、信息量最低 —— 像占位符没换掉。

**并且颜色不够用了**：6 个色块承担 14 个物品，等于「红色=止血丹，也是魔元丹」「绿色=蛇胆，也是定灵玉」。玩家靠颜色记物品的路径被自己堵死了。

### D. 同类内复用（8 组）

同类之间共用，危害小于 B，但仍有几组会混：

| 图标 | 共用的东西 | 是否可接受 |
|---|---|---|
| `📕` | 道具·破禁符 + **21 本不同法诀** | ✗ 21 本书长一样，只能读字 |
| `🟠` | 疗元丹 / 降尘丹 / 造化丹 | ✗ 三味丹同色 |
| `💎` | 下品灵石 / 极品灵石 | 可接受（同族，靠品质字区分） |
| `💥` | 爆裂符 / 爆裂符宝 | 可接受（同族） |
| `👘` | 云纹法衣 / 天蚕衣 | 勉强 |
| `🪙` | 金钱剑 / 张铁的铁牌 | ✗ 剑与令牌 |
| `🔱` | 赤铜短戟 / 洪荒古宝 | ✗ |
| `💊` | 九曲灵参丹 / 定灵丹 | 可接受（同族丹药） |

**关于 `📕` 的 21 本**：法诀类道具（`*·法诀`）全部用 `📕`。如果这是"类别图标"的有意设计（一本书就是书），那它需要**与个体图标分离**：列表里同类道具本可以共用族徽，但**必须保证族徽不跨类**。现状是 `📕` 还兼着「破禁符」（符箓），这就破坏了分类。

## 3. 硬数据：视觉权重差 2.67 倍

同字号下，emoji 的墨迹尺寸差异极大。测法：`canvas.measureText()` 取 `actualBoundingBox`，font-size 17px。

| 项 | 值 |
|---|---|
| 样本 | 68（ITEMS / SKILLS / SLOTS 可测项） |
| 平均墨迹宽 | 16.7px |
| 最宽 | `🗺` 24px = 1.41 × 字号 |
| 最窄 | `🗡` 9px = 0.53 × 字号 |
| 极差 | 15px = **2.67 倍** |

最宽的 12 个里，**6 个是纯色几何块**（🟤🟣⚪🔴🟠🟡）—— 这从数据上坐实了 C 节：它们不只是风格不同，是**体量也超标**。

最窄的 8 个全是线描符号：🗡 ⚡ 🏺 🛡 ⚔ ❄ 🩸 🥚。

> 注：字体取自测试机 Chrome（Windows）。真机是 Noto Color Emoji，具体数值会变，但"同字号下字形差异极大"这个结论与字体无关 —— 换任何 emoji 字体都成立。

## 4. 跨设备风险（比风格混装更严重）

emoji 由**系统字体**渲染，同一套代码在不同设备上图标长相完全不同：

| 设备 | emoji 字体 | 结果 |
|---|---|---|
| 华为 Mate 60 Pro（HarmonyOS） | Noto Color Emoji 变体 | 圆润、描边细 |
| iOS | Apple Color Emoji | 立体、有高光 |
| Windows | Segoe UI Emoji | 扁平、描边粗 |

这意味着「图标家族一致性」在 emoji 方案下**只能做到占位一致，做不到笔形一致**。想让图标真正成一套，只有一条路：**自绘像素图标**（跟 `sprites.js` 同一套字符网格画法，30 个精灵已经证明这条路能走通）。

这是本表最重要的一个判断：**要不要换，是产品决策，不是 UI 决策。**

## 5. 已落地的部分：图标位

**规格**：

```css
.ico { display: inline-block; width: 1.5em; text-align: center; font-style: normal; }
```

**依据**：1.5em @13px 正文 = 19.5px，装得下最宽的 18.4px。

**JS 侧**：`ico(x)` 辅助函数包裹，统一输出 `<i class="ico">🗡</i>`。禁止再手拼 `icon + ' ' + name`。

**已改 5 处**（`game.js`）：升级选择、功法页、灵宠蛋、灵宠页、同伴页。

**实测**：同伴页 4 行，名字起点全部 `61.5px` —— 唯一值，完全对齐；图标位宽恒为 19.5px。

**未改**：坊市货架（`.sr-main b`）、储物袋、装备行、快捷栏按钮。这些要么是按钮内自适应宽度（不影响列对齐），要么走另一套结构，留待下一轮。

## 6. 替换优先级（待决策）

按「改起来最小、收益最大」排序。**三项都需要拍板，我不擅自改图标内容** —— 换掉一个 emoji 就是改玩家的视觉记忆，属于内容决策。

| 优先级 | 事项 | 工作量 | 收益 | 风险 |
|---|---|---|---|---|
| **P1** | 9 个纯色几何块换成家族内的图形 emoji | 改 14 处 `icon` 值 | 消除最刺眼的异类；顺带解开 6 色块承担 14 物的死结 | 低（玩家不记 emoji，只记文字） |
| **P2** | 拆 B 类 34 组跨类共用里最明显的 8–10 组 | 改 10–15 处 | 图标恢复"能分类"的功能 | 中（要逐个想语义替换） |
| **P3** | 把 21 本法诀从 `📕` 拆开 | 改 21 处 | 法诀列表一眼能分 | 中（要定义法诀族的图标语言） |
| **P4** | 自绘像素图标替代 emoji | 99 个图标 × 字符网格 | 跨设备完全一致、真·统一线宽与留白 | 高（整轮工程，需先定风格） |

**建议路径**：先 P1（一晚的量，立刻见效）→ 再看 P2 → P4 作为独立立项。P3 可以等 P4 一起做，因为自绘时本来就要重画。

**不建议**：为了"统一"把所有图标都塞进同一个 emoji 风格 —— 那是在 emoji 的约束里打补丁，永远做不到真正一致。

## 7. 验收方式

```bash
node qa/verify-ui-spec.mjs     # 含图标位宽度、名字起点对齐断言
```

守门测试会验：
1. `.ico` 宽度恒为 1.5em（不随字号漂移）
2. 同一列表内多行的名字起点只有一个值（对齐没被后续改动破坏）
3. 图标位内不溢出（最宽图标 🗺 不撑破槽）

**不做的事**：测试不验"图标好不好看"、不验"语义对不对" —— 那是人的判断，脚本判不了。脚本只守机械可验的部分。
