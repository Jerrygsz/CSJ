# 第117轮 · 让同伴 / 灵宠的功法也「看得见」

## 一、起因

Jerry 的要求：

> 灵宠和同伴的功法也要和韩立一样，拥有既符合美术画风，又看着酷炫的效果呈现。

第116轮刚给 14 位随行者配好了原著技能，但呈现是**一圈环 + 几粒方块 + 一行纯文字飘字**。玩法上够了，画面上却像「凭空冒出来的一圈光」，跟韩立出手时的排场完全不是一回事。这一轮只补呈现，**伤害口径、冷却、境界联动、技能名一个字不动**。

## 二、先查：韩立的功法凭什么好看

只读摸下来，主角功法的视觉是四层叠出来的，而第116轮只用了最后一层里最弱的一种：

| 层 | 主角用的 | 第116轮随行者 |
|---|---|---|
| 起手 | `playerStrike()` 身体先缩再甩 + `spawnRune()` 脚下贴地法阵 + `Sfx` | 无 |
| 出手形 | `spawnSlash()` 三层弯月、`novaBlast()` 双环+12 道放射、`thunderStrike()` 天雷折线 + `spawnWeb()` 雷网 | 一个 `ring` + 几粒 3px 方块 |
| 水墨层 | `FX3`（pixelfx 适配层）：`rune` / `nova` / `poof` / `crit`，palette 过 `INK_HEX` 砍色 | 无 |
| 技能名 | —— | 纯文字飘字，和伤害数字挤在一起 |

### 两条机制性发现（决定了做法）

1. **`SC3_SOFT_RING` 会把 `ring` / `ray` 压淡**。水墨皮下 `drawPart` 把这两类统一改成 `rgba(74,70,60,0.8)` 且 alpha 乘 0.26。所以第116轮那个「主环」恰恰是全场最不显眼的东西 —— 不是配色没调好，是机制。**不受柔化的原语**是：`rune`（贴地法阵）、`slash`（弯月）、`bolt`（折线）、`web`（细线网）、`spark`（飞白笔触）、普通粒子、以及 `FX3` 的一次性特效。这一轮全部从这里取。
2. **`FX3.spawn` 和 `FX3.hold` 不是一回事**。`hold` 是常驻领域法阵，`draw()` 在浅纸下会把 `tag` 实例压到 0.42；一次性 `spawn` 不压。功法起手要看得见，只能用 `spawn`。而 palette 会自动过 `INK_HEX`，水墨皮里自动归墨阶 —— 这就是「符合画风」不用另配一套色的原因。

## 三、落地

### 3.1 六招共用的起手仪式（`allyCastFx`）

- `ent.skCast = 0.28` —— 绘制层据此走 `tfStrike()`，也就是韩立那条「含胸 → 挺胸探臂 → 收势」曲线。不传 `spr`，不去抓手绘三帧（那三帧只有韩立有），只借程序化变换。`ALLY_CAST_T` 与 `ATK_TOTAL` 由闸门比对，防止两处漂开。
- `spawnRune()` 脚下贴地法阵（主角 `fireActive` 同款，画在角色之前，不受柔化）。
- `FX3.spawn('rune', …, { pal })` 一次性像素符文，水墨调色板。
- 6 条细长 `spark` 飞白 + 一声 `Sfx.gem()` 起手清音。

原本 `allySpark` 是 3px 小方块，在宣纸上像撒纸屑；改成 `spark` 细长笔触（复用 `drawPart` 已有分支，尾巴朝速度反面拖），才像墨被甩出去。

### 3.2 六种形态各有笔势

| kind | 主特效 | 主角同款出处 |
|---|---|---|
| `bolt` 单体重弹 | 身前一道弯月刃 + `FX3('crit')` | `fireActive` 剑系 |
| `fan` 扇形多弹 | 三层错开的半月弧 + `FX3('poof')` 散形 | 风刃「半月形」/ 虫云散开 |
| `nova` 身周爆发 | 外晕环 + 内核环 + 12 道放射飞白 + `FX3('nova')` + 轻屏震 3 | `novaBlast` 金光爆发 |
| `chain` 多目标 | 每目标一道天落折线 + 落点雷网 + 双环 + `FX3('rune')` | `thunderStrike` |
| `chill` 范围定身 | 双环 + 三道交错细线网（7 条）+ `FX3('rune')` | `spawnWeb`，正好是「白液出口成网」「寒气封住」的字面画法 |
| `drain` 范围回补 | 外扩环 + **收缩环**（墨往身上收）+ 双层贴地法阵 + `FX3('pickup')` | 反向用 `ring`，读作「把生气收回来」 |

`FX3` 每次释放最多 2 个实例（起手 1 + 主 1），`fxpix.js` 的 `MAX_LIVE=6` 不会被打爆；屏震只给 3，比主角 Boss 技的 10+ 轻得多，不抢戏。

### 3.3 技能名改朱砂印蜕

`spawnText` 加可选 `opts.seal`，绘制时画「朱砂方底 + 细印边 + 方角 + 纸白字」，与第115轮顶栏增益小方印同一套语汇。全部 30 处飘字调用里**只有技能名这一处传 seal**，伤害 / 拾取 / 提示逐字节保持原样。

### 3.4 调色板不新造

数据表每条加一个 `pal`，只认 `fxpix.js` 的 `PAL` 四档：`xue` 朱砂（轮回神光）、`jin` 赭石/枯墨（虫云、神雷、蛛网、七星月体）、`qi` 花青（大衍诀、冰封、寒焰、风刃）、`mo` 墨（还魂术、黑水）。14 条分布 `1 / 4 / 7 / 2`。技能主色 `vfx` 仍是 `#hex`，交给 `inkify` 拦截器砍色 —— **没有新增任何颜色映射表**。

## 四、实拍自检：两轮返工

出图探针 `qa/_out/_shot-r117.mjs`（不入库），水墨皮与鎏金皮各出图，逐张肉眼看。

**第一版问题**：朱砂印蜕和伤害飘字挤在同一片，字读不清；扇形弯月弧度偏小。
→ 印蜕从 `y-26` 抬到 `y-50`、字号 12→14、底色调实、边框加粗；绘制分两遍，**seal 排在伤害数字之后画**；弯月 `rad` 20/27/34 → 26/36/46。

**第二版问题（放大图才抓到）**：印蜕里的字是**暗赭红色**，跟朱砂底几乎同色。
根因是 `inkify` 的饱和度判据 `s = d / (1 - |2l-1|)`：米白 `#fff8ec` 虽然看着接近白，`d` 小但分母更小，`s≈1`，被当成高饱和暖色砍成赭石 `[172,100,46]`。**只有 `d=0` 的纯灰阶才走 `s<0.22` 原样放行** —— 主角剑光的白芯用的正是 `#ffffff`。改成纯白后，放大图里「轮回神光」四个字清晰可读。

这一条已写成常驻断言，防止以后又被「优化」回米白。

## 五、闸门与验收

`qa/verify-ally-skills.mjs` 从 8 组 43 条扩到 **10 组 75 条**：

- **I 组 · 水墨呈现**：`__FR.allySkillFx(id)` 自包含临时靶子，逐招真实释放后数 `G.parts` / `G.texts` / `FX3.count()` 的产物 —— 不是看源码里有没有那行字。逐条对上六形态的笔势下限（法阵、弯月、折线、雷网、放射、印蜕、出手动作、像素特效层数），再静态兜一道原语确实写在释放段里；含 `INK_HEX` / `light:0` 画风纪律、`ATK_TOTAL` 一致性、印蜕字色与绘制顺序。
- **J 组 · 反向注入**：把法阵 / 像素特效 / 印蜕 / 出手动作 / 调色板 / 放射条数逐个抽掉，同一套 `validateFx` 必须报错。

十闸门全量回归两次全绿；实拍 8 张（六形态 + 印蜕放大 + 鎏金皮对照）无 JS 报错。双皮结论：水墨皮是淡墨折线 + 朱砂点睛，鎏金皮是朱砂双环 + 放射，**都没有出现彩色光污染**。

## 六、边界

- 只改呈现，不改变任何战斗数值；技能仍是战内状态、冷却不写存档、洞府只展示不手动开关（第116轮的边界原样保留）。
- `FX3` 一次性特效受 `MAX_LIVE=6` 限制；同屏同时释放的随行者最多 2 位，冷却 6~12 秒，实测不会互相挤掉。
- 鎏金皮的对照图只验了 `nova` 一招，其余形态在两套皮下共用同一套原语与 `#hex` 色值，由 `inkify` 统一决定砍不砍色。
