# 第94轮 · 交互浮层黑框补漏

**版本** `20261105B`　**起因** Jerry 再次反馈「还是有黑色框，文本看不清」，附实机截图：水墨皮洞府「炼丹」页点开「妖丹」料名，弹出的「去哪取」卡片是一块近黑底，里面的字几乎看不见。

---

## 一、为什么第 93 轮没查出来

不是改漏了一处颜色，是**审计的边界本身就是漏检区**：

1. `audit-contrast.mjs` 会跳过 `display:none` 的元素，而 `.item-tip` 初始就是 `display:none`，由 `showItemHint()` 点料名时才 `display:block`。
2. 它只 `push` 几个固定容器（`#caveBody`、`#worldmap .wm-panel` 等），而这张卡被动态插到 `body` 上、或就地插在点的那一行后面（`item-tip.inline`），两次都躲开了。
3. 结果：卡片沿用深色皮的近黑底 `rgba(18,14,9,0.97)`，而第 93 轮恰好把字色统一换成了墨色 —— **黑底 + 墨字，1.37:1**。

同一条边界还漏了两处静态文本（不在任何被扫容器里）：

| 元素 | 实测 |
|---|---|
| 洞府卷首题字 `.cave-quote`（`--accent-soft` 青灰） | **3.69:1** |
| 角落版本水印 `#ver`（半透明金 `rgba(201,162,74,.55)`） | **1.44:1** |

## 二、这次怎么查

新增常驻脚本 `qa/audit-contrast-live.mjs`，专门补交互态：

- 12 个洞府页签各点开料名 / 进阶行；世界地图展开一张卡；进战斗态
- **强制展开所有原本隐藏的顶层面板**（通关 / 道陨 / 升级 / 剧情 / 联机这些静态扫描永远看不到）
- 扫**全 `body`** 的可见文本，按「祖先链半透明逐层合成的背景 + 文字色 + opacity」算 WCAG 对比度
- 按「类名 + 字色 + 底色」聚合，禁用控件按 1.4.3 豁免；`SKIN=guigu` 严格断言（非豁免 0 类才算过）

改前命中 **45 处 / 6 类**，改后 **5 处 / 1 类**，唯一剩下的是禁用态「炼制」按钮 4.26:1（豁免）。

## 五、教训

1. **审计的边界就是漏检的边界。** 只扫「静态 + 固定容器」，等于宣布所有交互浮层免检。补漏不能靠再加一条 CSS，得先修检查方式 —— 所以这轮把交互态审计固化成常驻脚本，而不是用完即弃的探针。
2. **换皮最容易错位的组合是「字色走变量、底色写死」（或反过来）。** 第 93 轮把字色统一改成墨色，却没动 `.item-tip` 写死的近黑底，正好制造了黑底墨字。凡随皮肤变的颜色，前后两端必须一起变量化。
3. 深色皮的历史问题（全 body 扫描翻出 969 处）不属本轮；本轮所有新增规则都带 `guigu` 限定，不扩大它的欠账。
