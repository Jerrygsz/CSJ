# 第118轮 · 同伴 / 灵宠会自己打、会挨打、会殒落

## 一、起因

Jerry 的要求（原话）：

> 同伴灵宠功法也要有3种，护体，近程攻击，远程攻击，其CD时间也要和韩立当前境界对应功法的攻击频率同步齐平，要有爽感，且他们的活动范围可以在韩立可视范围内，自由移动打怪，不用随时围绕韩立，被击中和碰撞也会要承受伤害，他们血量根据韩立的当前血量满血50%去参考设计，但是不显示血条，死亡之后10秒自动复活，复活自动扣去10000灵石，灵石不够就不复活，打完地图，出去赚够钱，洞府处交钱复活。

第116 / 117 轮把 14 位随行者做成了「跟随炮台」+ 各有本命绝学水墨特效。这一轮是**玩法级改造**：从「不会死、永远贴着主角、按固定冷却放一招」改成真正参战的第二个单位。改动面比前两轮大得多。

## 三、定口径（三个关键决定）

### 3.1 三类功法是「运使方式」，不是新招式名

`canon/combat.md` 规定技能名必须原著可查，禁止自造「XX斩 / XX诀」。第116轮已给 14 位随行者逐条核过本命绝学，这一轮若再造 42 个招式名必然全是自造词。

所以 `window.ALLY_ARTS` 里的 `护体 / 近身 / 远击` 是**三条常规律动的功能标签**，只回答「这一击怎么运使」；每位随行者唯一具名的招式仍是 `ALLY_SKILLS` 里那一条。名字刻意避开 `诀 / 斩 / 爆 / 功 / 法 / 术` 后缀，只留单字标签 `护 / 近 / 远`。闸门用 `/[诀斩爆功法术]$/` 与 `/^[护近远]$/` 两头卡住。

### 3.2 CD 齐平：直接抄主角那一行，再钳一个下限

| 类别 | 绑定主角功法 | 取 CD 的来源 | 说明 |
|---|---|---|---|
| `guard` 护体 | `nova` 定神符 | `skillAtk.cd(a, lv)`（4.5 / 0.3 / min 2.5） | 护罩是间歇开合，跟爆发技一个节奏 |
| `melee` 近身 | `frost` 冰冻术 | `cdHit = 0.5` | 贴身快打，取命中间隔而非技能冷却 |
| `ranged` 远击 | `sword` 驱物术 | `cd = 0.85` | 韩立平A 的节奏 |

三者统一乘 `hasteMul() * atkMul()`，即境界涨 → `G.realm.atk` 涨 → `atkMul()` 降 → 随行者跟着变快，与韩立同口径。

**但完全照抄会糊屏**：道祖境主角 `sword` 间隔可低到约 `0.0439s`，两个随行者一秒能刷几十发。故设 `ALLY_CD_FLOOR = 0.18`：低境界三类 CD 与主角同公式，高境界钳到 0.18s。闸门逐档拨 `G.realm.atk` 验证单调递减且末档正好落在下限。

### 3.3 活动范围：可视矩形，不围绕主角

`ALLY_VIEW_EDGE = 22`，`allyClampView()` 把坐标夹在 `cam.x+22 … cam.x+W-22`、`cam.y+22 … cam.y+H-22`。`allyTarget()` 只打屏内敌人，`allyMove()` 按自身形态追近（近身型 `want=30`）或拉开（远程型 `want=132`），没敌人时在自己视野里游走。翻面看自己的 `dir`，不再跟韩立一起翻。

### 3.4 生死经济：欠费台账是关键

第一版我写成了「灵石攒够的下一帧就自动扣钱复活」，这在实拍复核时被判为**偏离口径**：用户明确说「灵石不够就不复活……出去赚够钱，洞府处交钱复活」，而钱一够就自动起身会让洞府「交钱复活」按钮形同虚设；洞府面板当时的文案也自相矛盾。

改成两条台账：

- `save.allyDead[id] = Date.now()` —— 殒落时间，绝对时间，跨地图 / 跨会话不丢。
- `save.allyOwe[id] = true` —— **欠费**。十息到点钱不够就记一笔，此后哪怕在别处打怪攒够钱也不自动起身，必须回洞府点「交钱复活」。交钱成功同时清两本账。

于是三条路径各自成立：钱够 → 十息自动扣 10000 复生；钱不够 → 欠费不起身；欠费 → 出去攒钱 → 洞府交钱。旧档读档补空账，删档重修自然清空。

## 四、落地

### 4.1 数据表（`js/late3.js`）

`window.ALLY_ART_KINDS = ['guard','melee','ranged']`、`window.ALLY_ARTS` 三类模板（含 `cdKey` / `pow` / `rad` / `count` / `pal`）、`window.allyArtOf(id, kind)` 把「本命绝学的威力/形态/色板」与「这一类的运使方式」合成一条轻量技能。近战型随行者（`nova / chill / drain`）走贴身，其余走远程。

### 4.2 释放引擎与自由行动（`js/game.js`）

- `ALLY_KINDS` 扩到 9 类，`castAllySkill()` 新增三个分支：护体（双环合拢 + 贴地阵 + 像素符文 + 设 `guardT`）、近身（双弯月 + 小范围环 + 范围伤害）、远击（弯月 + 两道追踪刃光）。
- 三类带 `light: true`：不做技能名朱砂印蜕、不做大起手动作、不播大音效、法阵缩到 14px —— 本命绝学仍是节奏上的**重音**，常规功法是**轻音**，密集出手不糊屏。
- `allyArtCd()` / `allyClampView()` / `allyTarget()` / `allyMove()` / `castAllyArt()` / `tickAllyArts()`；`updatePet` / `updateMate` 不再写「追主角坐标」，改走 `allyMove()`，`dead` 直接 return。

### 4.3 伤害出口（8 处接线）

`hurtAlly()` 是随行者唯一受击入口，带 0.55s `iv` 去重、`guardT` 期间减伤 45%、朱砂飘字与命中火花，**不碰主角任何状态**。接线点：己方/敌方弹幕碰撞、小怪贴身、地刺、光柱/横扫、Boss 撞击、困阵/寒气罩全场招、爆发波及。`armorRate()` 并入 `allyGuardBonus()`：护罩罩到 96px 内的韩立时，也给他加 0.18 减伤（仍受 0.62 硬顶）。

### 4.4 生死经济与洞府

- `makeAlly()` 统一三处创建点，`maxhp = Math.round(G.player.maxhp * 0.5)`，**不显血条**。
- `killAlly()` 写 `allyDead`、`reviveAlly()` 清两本账、`tickAllyRevive(dt)` 每帧一次、`payReviveAlly()` 洞府交钱。钱不够的殒落提示也不再说「十息后复生」，改为「出去攒够钱回洞府交钱」。
- 洞府灵宠页 / 同伴页：顶部说明三类功法与当前 CD、血量与复活规则；殒落行显示「已殒」「殒落中 · 复活需 10000 灵石」「欠费待交 · 不会自动复生」以及 `data-revive` 按钮。按钮**不设 disabled**（点击事件会上不来），钱不够在点击里提示。
- 死亡只画一枚淡墨「殒」字；活着画朱砂护罩、受击红边、各自的 `dir`。

### 4.5 DebugAPI

`__FR` 新增 `allyArts` / `allyArtCd` / `allyArtCds` / `allyState` / `allyHurt` / `allySetGuard` / `allyTickRevive` / `allyPayRevive` / `allySetDeadMap` / `allySetOweMap` / `allySetPos` / `allyMoveTick` / `allyCastArt`。闸门读的全是真实运行产物，不复刻算法。

## 五、实拍自检返工（三处）

出图脚本 `qa/_out/_shot-r118.mjs`（不入库）在 430×900 水墨皮实机拍了自由行动、三类功法、护体罩、受击、殒落、洞府欠费共 15 张。

1. **主角弹幕把随行者的轻笔势淹没了** —— 第一版出图每轮只清了 `G.parts` / `G.texts` / `FX3`，没清 `G.bullets`，蓝色剑影一直累积。修脚本（不改游戏）后，护体双环、贴地阵、近身弯月、远击刃光都看得见了。
2. **护体罩在浅纸底上太淡** —— 原绘制只有一条 `alpha 0.18~0.46` 的细朱砂圈。改为「极淡朱砂晕填充 + 1.8px 朱砂印边 + 一圈外细印边」，随 `guardT` 淡出；实拍里成了可读的朱砂同心印，不抢主角。
3. **洞府「三功」竖排成六行** —— 根因不是文案长，是 `.rr-main b { display:block }`，我给三个标签各包了 `<b>` 导致每个词独占一行，把殒落状态和交钱按钮挤到滚动区外。改成纯文本 + `white-space:nowrap`，欠费说明另起一行红字；重拍后「三功：护体 · 近身 · 远击」一行、两行红字、`交钱复活 / 收回 / 放生` 按钮全部同屏可见。
