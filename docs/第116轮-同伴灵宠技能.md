# 第116轮 · 给同伴和灵宠各加一门原著里的本事

## 一、起因

Jerry 的要求：

> 给同伴和灵宠都加上符合剧情原著小说的技能，根据主角境界增长适当威力，作为辅助攻击。

三个词要同时满足：**符合原著**（不能自造技能名）、**随境界增长**（不能与后期战斗脱节）、**辅助攻击**（不能盖过主角输出）。

## 二、先查：现在它们是什么

只读摸下来，3 位同伴（`window.MATES`）和 11 只灵宠（`window.PETS`）其实都是同一个东西 —— **跟随炮台**：

- `updatePet(dt)`：跟在主角身后半步，冷却到了朝 430px 内最近的敌人发一枚追踪弹，`dmg = (G.realm.dmg * 70 + 10) * def.dmg`
- `updateMate(dt)`：站在另一侧，470px 内发一枚更重更慢的弹，`dmg = (G.realm.dmg * 90 + 16) * def.dmg`
- 两者都无血条、不受击、不占快捷栏，只有一个普攻 `cd`。

所以「加技能」＝给每个跟随实体再挂**一条独立的冷却与出手形态**，不动原来的普攻。

## 三、三个设计决定

### 3.1 技能名：逐条回原著查，不造词

`canon/combat.md` 第四节的硬规矩是「技能命名必须原著可查」。先拿两本原文（人界篇 775.9 万字 + 仙界篇 477.8 万字，UTF-8）做词频与共现探针，产出了 `canon/ally-skills.md` 这份台账。

几个查证中改掉的判断：

| 起初想用 | 查完发现 | 结果 |
|---|---|---|
| 大衍神光 | 全书 **0 次** | 删掉，改用「大衍诀」（202 次） |
| 幽冥鬼爪（啼魂） | 是仙界篇**五品仙器**，啼魂想买的东西，不是它的招式 | 删掉，改用原文直书的「啼魂的摄魂神光」 |
| 金丝（噬金虫王） | 那段「化为无数细长金丝」是**符箓**变的，不是虫吐的 | 删掉，虫王仍用「虫云」 |
| 分神（大衍神君） | 225 次里绝大多数是「无法分神顾及」的动词 | 不用 |
| 金罡灭魔神雷（蟹道人） | 韩立金雷竹一脉，与蟹道人共现 0 次 | 删掉 |

14 条里 **10 条 direct**（原文里这角色确实使过/有过这能力），**2 条 ability**（体质名/术法名，如「七星月体」「还魂术」），**2 条 borrowed**（原著通用词借用，如云翅鸟配「风刃」、蟹道人配「神雷」）。后 4 条全都在台账和 `canon.note` 里写明「非原著独立招式」，不把游戏效果冒充原著事实。

即便关联最弱的云翅鸟，也如实写清：原著它只是墨大夫的监视鸟，不参战；游戏里它已是随行灵宠，故取「比强弓利箭还快」之意借风系法术名。

### 3.2 威力：不另造一条等级曲线

这是最容易做错的地方。现有灵宠/同伴的普攻已经预乘了 `G.realm.dmg`，而 `damageEnemy()` 内部的 `dmgMul()` 又含 `(1 + G.realm.dmg)` —— 本来就是二次放大。新技能**不能再叠一次**。

定的口径：

```
技能伤害 = sk.pow × 档位倍率   →   damageEnemy(e, ...)   →   dmgMul() 把主角境界/装备/功法/增益一起算上
```

- 主角涨多少，随行之人的这一招就跟着涨多少，与主角主攻永远是同一条曲线，不会后期脱节也不会喧宾夺主。
- 额外叠 `ALLY_SKILL_TIERS` 四档，按**长期修为** `save.cultivate.level` 分：初悟 ×1.00 / 精进 ×1.30 / 圆熟 ×1.60 / 通玄 ×1.95。门槛直接取 `js/skills.js` 的 `rangeModel.BANDS`（36 / 112 / 260），不另造一套境界线。
- 基础威力 10~30、冷却 6~12 秒。对比功法 `base 8~14 + perLv 3~6` 且每秒多发，技能是明确的「隔一阵来一下」。

### 3.3 出手：自动、独立冷却、六种形态

数据表放 `js/late3.js`（所有常驻 QA 沙箱都会加载它，不用改脚本链），引擎放 `js/game.js`：

| kind | 形态 | 用到它的 |
|---|---|---|
| `bolt` | 单体重弹、高穿透 | 七星月体、黑水 |
| `fan` | 扇形多弹 | 虫云、傀儡术、风刃 |
| `nova` | 身周范围爆发 | 轮回神光、寒焰、虫云（王） |
| `chain` | 最近多目标、逐跳衰减 | 大衍诀、神雷 |
| `chill` | 范围 + `stunT` 定身 | 摄魂神光、冰封、蛛网 |
| `drain` | 范围 + 按伤害回补主角气血 | 还魂术 |

`tickAllySkill(ent, ownerId, dt)` 挂在 `updatePet` / `updateMate` 里、普攻那句 `if (G.state !== 'play') return;` 之后、`pt.cd` 的 early return **之前**，所以普攻回气不会挡住技能计时。进图先蓄半程冷却，避免一开打就齐放。

联机客机的直接伤害类走 `Coop.reportHit(e._id, dmg)` 上报房主，不本地扣权威怪的血 —— 与现有弹幕命中同一套规矩。

## 五、UI

洞府的「灵宠」「同伴」页各补两处：

- 段首说明当前档位：「眼下 **圆熟**（威势 ×1.60），化神之后，神通渐成」；
- 每行多一行 `【技能名 · N秒】说明`（冷却前置，免得被挤到行尾折行）。

没有加按钮、没有加开关 —— 技能是自动的辅助攻击，不该多一层操作。

## 七、闸门

`node qa/verify-ally-skills.mjs`，八组 43 条：

- **A 覆盖**：页面真实加载的 3 同伴 + 11 灵宠一个不漏；源码正则再兜一道（认「同一行带 `spr` 立绘字段」，避免把 `m_` 开头的材料误当实体）
- **B 原著**：技能名 / 词频 / 摘句 / 关联强度逐条对上台账与**已固化的原文词频基线**；无「XX斩 / XX爆」；`ability` / `borrowed` 必须带说明
- **C 数值**：六形态齐、威力 10~30、冷却 6~12、四档门槛与 `rangeModel.BANDS` 一致
- **D 境界**：14 条技能在 1 / 36 / 112 / 260 四档威力严格递增；`setLevel` 改到哪一档，探针读到哪一档
- **E 实机**：进后山放四个不死靶子，逐个真实释放 —— 直接伤害类见掉血、弹道类见弹幕增量、六种形态全跑到、无 JS 报错
- **F 冷却**：源码断言 `tickAllySkill` 真的挂在两个 update 上、冷却回写、客机走房主上报
- **G 反向注入**：把自造名 / 删一条 / 改词频 / 换摘句四份坏数据喂给**同一个校验器**，四份都必须被拦下
- **H 台账**：14 段与代码表逐字段一致

## 八、已知边界

1. 4 条 `ability` / `borrowed` 是明确标注的引申，不是原著招式；要更严可以把它们换成纯 `direct`，但云翅鸟、蟹道人、银月原著里确实没有带名的攻击招。
2. 技能是战内状态，`skCd` **不写存档**（与普攻 `cd` 一致）；换宠 / 换同伴会重新计时。
3. 洞府只展示，不提供手动开关 / 装配 —— 若要让玩家自己选带哪一门，是另一个需求。
4. 一次性原文探针 `qa/_out/_canon-ally-*.mjs` 不入库、不参与运行；闸门用的是已固化在脚本里的词频基线，不依赖 `D:\Games\CSJ` 那两本 txt 在线。
