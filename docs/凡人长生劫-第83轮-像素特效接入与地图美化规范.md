# 凡人·长生劫 —— 像素特效层接入与地图美化规范（第 83 轮）

**结论先行**

1. **pixelfx 能接，而且已经接上了**（闪身·暴击·Boss 法阵·领域法阵四个点位，294 项冒烟全过）。但它**不能整包照搬**：它的渲染模型（彩色实心 + 加法发光）默认场景是暗的，而我们的战斗打在宣纸白底 / 草地绿底上，加法光等于没画。这一条不改，接进来就是一层灰。
2. **它的尺寸是对的，笔触也是对的**（1px 起线、法阵是细环），错的是**颜色与合成**——这两个我改在了适配层里，不动上游源码，将来升级上游不会冲突。
3. **地图美化它一点忙也帮不上**。pixelfx 是纯特效库，没有地形、没有瓦片、没有装饰物。地图那部分只能自己做，我在第 6 节给了可执行的方案与验收口径。
4. 代价是真实的：**6 个特效同屏 = 1.95ms/帧**（本机桌面 Chrome）。已按上游 30fps 节流 + 同屏上限 6 兜住，低端机仍需实测。

## 1. 现状评审：战斗层真正的问题不是「特效不够」

拿 `qa/shot-H-boss.png`（广寒界·通灵傀儡）做六维打分：

| 维度 | 分 | 依据 |
|---|---|---|
| 剪影可读性 | 2/5 | 14px 的角色叠在同样 14px 量级的水墨远山与树影上，涂黑后和背景糊成一片 |
| 明度层级 | 2/5 | 纸底（亮度约 220）、远山（约 190）、角色白袍（约 225）——主体与背景只差 5~30 档，灰度下几乎同值 |
| 构图与负空间 | 4/5 | 一角构图、中央留白，这套语言是成立的 |
| 风格一致性 | 4/5 | 水墨 + 像素精灵 + 细线特效是一套的；但 Boss 美术层半透明压在场上，和判定圈抢同一块区域 |
| 技术合规 | 4/5 | 480 逻辑宽、最近邻、纸纹 96 无缝，没有明显硬伤 |
| 可用性 | 3/5 | 特效全是细线 + 低透明，不挡判定；但**主角在混战里容易丢** |

**判定：小改**。要动的是「主体与背景的明度差」和「战斗层的信息分层」，不是再加特效。加特效只会让第 2 条更糟。

## 2. pixelfx 的可用边界（实测，不是推测）

我把它最像我们的六张特效单独抠出来放大比对（`qa/shots/one-*.png`、`qa/shots/ink-*.png`），得到四条硬结论：

| # | 上游的前提 | 我们的现实 | 处理 |
|---|---|---|---|
| 1 | 效果靠 `light` 缓冲做加法发光，暗场越亮越好看 | 纸底亮度 220+，加法光加完还是白 | **一律 `light: 0`**，改由色阶最暗两档自己承担轮廓 |
| 2 | 每个特效带自己的原色（紫蓝 / 洋红 / 亮橙） | 鬼谷皮有一套砍色纪律：只留赭石 + 花青，朱砂点睛 | **六档色阶全部过 `window.INK_HEX`**，与画布同源 |
| 3 | 假设角色约 40px 高 | 我们角色 14px | **不缩放**（缩放会破坏像素网格），只挑「天生小」的特效，再按点位定档 |
| 4 | 一帧就是一张 136×80 到 216×136 的位图，逐帧重建 | 手机端每帧预算只有十几毫秒 | **按上游 `meta.fps`（30）节流** + 同屏上限 6 + 实例池复用离屏画布 |

放弃的四类效果：**Fire / Explosion / Weather 全家**（体量大、实心块多，14px 角色边上就是一坨）、**moves 全家**（自带灰色假人，会和我们自己的角色打架）、**带 actor 的 53 个**（同上）、**transitions**（是全屏转场，节奏不匹配）。

## 3. 接入架构

```
js/vendor/pixelfx.bundle.js   ← 上游 src/core + 6 个特效，esbuild 打 IIFE（58KB）
        ↓ window.PixelFX
js/fxpix.js                   ← 适配层：坐标 / 色阶 / 开关加法光 / 节流 / 实例池
        ↓ window.FX3
js/game.js                    ← 四个接点，全部 `if (window.FX3)` 守卫（无头测试环境自动跳过）
```

上游源码原样放在 `vendor/pixelfx/`（`src/core` + 选中的 6 个 `src/fx` + `LICENSE` + `NOTICE.md` + `entry.js`），**不改一行**。重新打包：

```bash
npx esbuild vendor/pixelfx/entry.js --bundle --format=iife --minify --outfile=js/vendor/pixelfx.bundle.js
```

API：

| 调用 | 用途 |
|---|---|
| `FX3.spawn(key, x, y, {pal, flip, seed, scale, opts})` | 一次性特效，世界坐标 |
| `FX3.hold(tag, key, follow, opts)` / `FX3.release(tag)` | 常驻特效（领域/环绕），每帧按 `follow()` 跟位 |
| `FX3.update(dt)` / `FX3.draw(ctx)` / `FX3.clear()` | 推进 / 绘制（须在 `translate(-cam)` 之后）/ 清场 |

当前注册：`hit`（命中星闪）、`crit`（暴击星爆）、`rune`（地面法阵，4s 循环）、`nova`（灵力爆发）、`poof`（散形/现形）、`pickup`（拾取迸发）。

## 4. 色彩与规格（已确认，后续不得擅改）

**四套色阶**，每套 6 档，从最暗到最亮：

| 名 | 用途 | 色值 |
|---|---|---|
| `qi` | 身法 / 灵力 / 冰域 | `#16262b #20434b #2f6f78 #4e9fa6 #93d6d3 #f2fffd` |
| `jin` | 命中 / 金光 | `#2a1c06 #5c3a0d #96651a #d0a03a #f4dfa6 #fffdf2` |
| `xue` | 暴击 / 受创 | `#2a0510 #5c0a1c #a3142a #d8352c #ff8a3c #ffe6a8` |
| `mo` | 魔道 / 重力域 | `#150e1c #2a1a36 #472a5e #7a3f96 #bb7ad8 #f2dcff` |

水墨皮（`skin === 'guigu'`）下，以上 24 个色值全部经 `INK_HEX()` 再映射一次，落成朱砂 / 赭石 / 花青 / 墨阶——与画布画笔同一条规则，所以不会出现「画布是墨的、特效是彩的」。

**尺寸纪律**：一律 `scale: 1`。上游特效按 1px 网格作画，任何非整数缩放都会毁掉像素边界。需要更小就换更小的特效，不要缩。

**时长**：跟上游 `meta.duration`，不加速。命中类 0.5~0.9s，法阵类循环常驻。

## 6. 地图美化（pixelfx 不覆盖，这条必须自己做）

**现状问题（按严重度）**

1. **没有地标**：整图 96px 平铺底纹 + 随机撒树，走到哪都一样，玩家攒不下空间记忆。
2. **装饰物与角色同亮度**：树、草、角色用同一个明度，深度塌陷，主角在树影里直接消失。
3. **地图之间只差色相**：后山绿、广寒灰——换个颜色就当换了地方，识别度不足。

**方案：三层 + 一道遮罩**（引擎无关，纯 canvas 代码绘制）

| 层 | 内容 | 规格 | 约束 |
|---|---|---|---|
| L0 底纹 | 每 biome 一张 96×96 无缝纹 | 现有 `buildGrass()` 扩成按 biome 取色 | 相邻两图的底色**明度必须差 ≥ 18 档** |
| L1 中景装饰 | 石 / 树 / 残垣 / 水洼，按 biome 各 6~8 种 | 单件 24~48px，密度 1 件 / 6000px² | 明度压到背景 **+12 ~ +20**，饱和度 ≤ 背景 +10% |
| L2 地标 | 山门 / 断碑 / 枯井 / 尸骸堆 | 64~96px，每图 1~3 个 | 明度压到 0.55，**画在特效层之下**，永不被特效盖住 |
| M 遮罩 | 四周渐暗 + 中央微亮 | 现有 `washLayerOf()` 扩到非水墨皮 | 压暗 8~12%，把视线收回中心 |

**验收口径**（可执行，不靠感觉）

- 把整屏缩到 20%，涂成灰度：仍能说出「这是哪张图」→ 过。
- 主角 14px 涂黑，与背景灰度差 ≥ 25 档 → 过。
- L2 地标在满屏特效下不被完全遮住 → 过（特效层必须后画）。

**与 pixelfx 的关系**：无。它是特效库，不产出地形/瓦片/装饰物。可以用它的 `tools/render.mjs` 把某个特效导出成 PNG 当参考，但地图素材得自己画。

## 7. 预算（实测数字，不是估计）

环境：Windows / Chrome / 420×820 视口 / deviceScaleFactor 2。

| 同屏实例 | 单帧耗时 |
|---|---|
| 0 | 0.04 ms |
| 3 | 1.69 ms |
| 6（上限） | 1.95 ms |

对照：整场 Boss 战原帧耗 0.087ms（第 80 轮口径），即特效层在满负载时把帧耗抬高约 20 倍绝对值、但仍在 2ms 内。**结论：桌面与中端机可接受；低端机需实测验证（标红）**。

优化已做两条，缺一条都到不了这个数：

- 按上游 `meta.fps`（30）节流：帧号没变就不重建像素（砍掉一半）；
- 实例池复用离屏画布 + `ImageData`，避免每发一次特效就 new 一张画布。

若要再压：`MAX_LIVE` 从 6 降到 4（约省 0.4ms/帧），代价是暴击时可能顶掉一个 Boss 法阵——不建议，法阵属于「信息」不是「装饰」。
