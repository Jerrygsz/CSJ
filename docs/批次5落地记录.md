## 四、实拍复盘

第七次印证「**结构通过 ≠ 能用**」：147/0 全绿后逐张看 22 张实拍，整体达标——全灰阶、大片留白、无实心碎块、无彩色、主景可读。三处需点名：

1. **tianyuan / shisan 看起来像同一张**：初版两者构图字节相同（clanhall + 同一组 band/breath/clusters/focusScale/palette），视觉上都是「鸟居式门架 + 放射阵环」。改 `shisan` 为 `frame` 章法 + `breath3` 后，布局明显不同，会盟场景与天渊城拉开层次。
2. **tianpeng 偏密**：初版 `band / breath2` 在 480 宽画幅上铺到 92 个装饰，虽成丛不杂乱但越留白上限。改 `frame / breath3` 降到 54，悬浮宫殿 + 圣池之间留白更足。
3. **xuechi 视觉不够「暗」**：逐像素探针确认积墨罩已烘（`maxAlpha 121`、四角径向浓墨晕），但浅宣纸底上整体观感偏亮。这是「幽暗靠积墨罩 + 浓墨主景、不把纸涂黑」的灰阶纪律使然，与用户拍板的「做 UI 柔化 + 血池/黑煞教单独调幽暗 + 严守灰阶」一致，未改游戏数据、未引彩色。

**可复用经验**：① 加批时 `composition` 必须入「唯一性」校验——`focusCase` 相同不等于构图相同，拼装字段（layout/breath/clusters/focusScale/palette）要整体比对；② 留白上限 `decorMax=70` 仍靠 F 组断言兜底，正确解法是调真源 `breath/clusters/layout`，不是抬阈值；③ 散文里的批次数（剩余未收录、补铺宣纸张数）是隐形技术债，生成器加动态数字校验才收口。
