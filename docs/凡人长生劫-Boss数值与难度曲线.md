# 《凡人·长生劫》Boss 数值与难度曲线（第 74 轮）

> 本文记录 Boss / 小怪 / 精英数值的**推导方式**与**验收口径**，不是数值表本身。
> 数值表在 `js/balance.js`，由脚本生成，别手改；要改就改生成器再重跑。

---

## 一、这一轮解决的问题

改之前，全库 81 张带 Boss 的图，症状是四个：

| 症状 | 证据 |
|---|---|
| 开局第一关打不动 | 后山狼妖 1100 血 / 玩家一秒 11 伤 = 100 秒起，首战劝退 |
| 中期 TTK 抖 16 倍 | 最短 6.5 秒，最长 105 秒，还有 2 张打不动 |
| 后图比前图容易 | 108 级的 `luoyun2` 要 102.8 秒，紧邻的 110 级 `liudao` 只要 61.8 秒 |
| 36 级以后危机感归零 | Boss 单击占玩家气血从 15% 一路跌到 0.1%，640 级要挨 1166 下才死 |

根因只有一句话：**玩家气血随境界指数暴涨，Boss 血量却是历年手写的绝对值**，两条曲线各走各的。

## 二、数值怎么定的（两步，缺一不可）

### 第 1 步：解析模型算「玩家大概多少秒伤」

`qa/balance-model.mjs` 只读功法表里写死的东西：伤害、弹数、间隔、境界倍率。
它不看运气、不看走位，可以精确复现。

踩过的两个坑，都记在模型注释里：

1. **境界奖励功法是常驻的**。`applyRealm()` 把每层 `skill` 写进 `p.skills`，而 `equippedEntries()`
   读的是整张 `p.skills`，不是存档里的 `equipped`。也就是说境界一路领的十几门功法**同时开火**，
   槽位数只管存档那一份。第一版模型按槽位算，低估后期 4 倍。
2. **`realm.atk` 会压缩 cd**。`atkMul() = 1/(1+realm.atk)`，640 级时 `realm.atk≈8`，
   等于每秒出手 9 次而不是 1 次。第二版漏了这个，再低估 7 倍。

### 第 2 步：闭环校准，用实测 TTK 反推血量

模型算不出 Boss 会不会风筝、后段会不会召唤替死、二阶段有没有无敌帧。
实测下来**同等级同血量能差 4 倍**（lv132 的 `zhenchan` 41.7 秒 vs `muzu` 177.2 秒）。

所以血量不按模型拍板，而是：

```
hp_new = hp_old × 目标TTK / 实测TTK        （damped 0.7，只修 15~70 秒之外的图）
```

这个比值天然包含风筝、召唤、无敌帧。迭代两轮到 81/81 全部落进目标带。

> 为什么要阻尼：TTK 对血量**不是线性的**。Boss 活到二阶段后输出效率掉一档，
> 于是 `hp×2` 可能换来 `TTK×4.4`（`xuese` 2100→14.8 秒、4300→81 秒，来回横跳）。
> 满额修正会震荡，所以步长 0.7、系数上钳 2.0 下钳 0.5。

## 三、目标带（裸装基准：无装备、无永久丹药）

| 地图类型 | TTK | Boss 单击占气血 | 裸装几击 |
|---|---:|---:|---:|
| 普通战斗图 | 30s | 7.5% | 13.3 |
| 剧情战 | 36s | 9.0% | 11.1 |
| 卷末守关 | 44s | 10.5% | 9.5 |
| 首关（教学） | — | 4.5% | 22 |

**为什么单击是 8~10%，不是最初定的 12~16%：**
站桩实测发现，12% 时几乎所有图都打成「和 Boss 同归于尽」——死亡时间恰好等于 TTK。
降到 8~10% 后，裸装站桩是残血险胜，走位则有余量。玩家带装备（减伤 20~55%）就更从容。

**首关为什么单独放宽到 4.5%：** 第一只怪是教学局，站桩也得能赢。

## 四、真正杀死「危机感」的不是血量，是弹幕伤害写死

这是本轮最重要的发现，值得单独记。

改完血量后第一次承伤测试，**后期完全不掉血**：lv520 的 Boss 单击 46235，
玩家打完一整场只掉 0.1% 气血。

一路查下去，`game.js` 里 9 处弹幕生成把伤害写成了常数 11~15：

```js
aimFan(b.x, b.y, ang, n, spread, 190, 14);        // 扇形散射，单发 14
ringBurst(b.x, b.y, 14, 185, 12);                 // 环形弹幕，单发 12
```

这两个数从第一版留到现在。lv1 时 Boss 单击是 15，弹幕 14 —— 合理；
lv520 时 Boss 单击 46235，弹幕还是 14 —— 法师系 Boss 等于不会伤人。

修法：所有弹幕伤害由 `bShot(boss, k)` 从本表派生。

| 招式 | 系数 | 理由 |
|---|---:|---|
| 扇形散射 `aimFan` | 0.42 | 一轮打出去 5~11 发 |
| 环形弹幕 `ringBurst` | 0.26~0.28 | 贴身会被套好几圈 |
| 螺旋弹幕（虫群） | 0.80 | 原本已是从 `b.dmg` 派生，保留 |

改完后期承伤从 0.1% 回到 60~80%，危机感回来了。

**教训：数值失衡经常不在“数值表”里，而在代码里某个忘记加倍的常数上。**
所以守门脚本除了查表，还要静态扫 `game.js` 的弹幕调用点。

## 五、验收口径（三条铁律）

`qa/balance-verify.mjs` 的测量方法踩了三轮坑才稳定，任何一条改回去都会量出假数据：

1. **一图一页**。83 张图挤一个页面，上一张改过的 `MAPS` / 冻过的经验 / 没清干净的 Boss 会一路带下去，
   量出「后山一秒掉 0.17 血」这种鬼数。
2. **冻经验**（`p.next = 1e12`）。小怪掉经验触发升级选卡，卡片挡住主循环，
   计时被截断 —— `yanjia` 因此被量成「242 秒打不动」。
3. **必须贴脸追击**。Boss 会自己保持 170~180px 距离，超出技能范围就打不到；
   站着不动量出来的 dps 会掉到真值的 1/20（`guxiu` 803 → 45）。

### 结果

| 指标 | 改前 | 改后 |
|---|---|---|
| TTK p10 / p50 / p90 | 6.5 / 28 / 105 秒 | 28.7 / 34.8 / 42.1 秒 |
| 落在 15~70 秒 | —（两图打不动） | 81 / 81 |
| Boss 单击占气血 | 15% → 0.1% | 7.5% ~ 10.5% 全域恒定 |
| 裸装几击 | 6.7 → 1166 | 9.5 ~ 13.3 |

## 六、守门

`qa/verify-balance.mjs` 断言四条，已用坏样本证红：

| 断言 | 判据 | 证红方式 |
|---|---|---|
| 覆盖 | 81 张带 Boss 的图都有条目，无死条目 | 删一条 |
| 单击 | 占裸装气血 6%~13%（首关 4%~6%） | 把 `dadi` 改成 50% → 报警 |
| 弹幕 | `game.js` 里弹幕调用必须走 `bShot` | 改回写死 12 → 报警 |
| 时长 | audit.json 里 ≥90% 落在 15~70 秒，无打不动 | 喂坏 audit |

> 「恰好卡在门槛上通过」说明守门已经退化成空转门 —— 所以每条都先用已知坏样本证红过。

## 七、重跑顺序

```bash
node qa/balance-model.mjs        # 1. 出解析模型 model.json
node qa/gen-balance.mjs          # 2. 生成 js/balance.js（无 cal.json 时是纯模型值）
node qa/balance-verify.mjs --all # 3. 全库实测 TTK → audit.json
node qa/calibrate.mjs            # 4. 出带的图重算血量 → cal.json
node qa/gen-balance.mjs          # 5. 再生成（此时带校准）
# 6. 重复 3~5 直到 81/81 在带内（通常两轮）
node qa/verify-balance.mjs       # 7. 守门
node qa/dump-stats.mjs && node qa/gen-stats-doc.mjs   # 8. 刷新《数值总表》
```
